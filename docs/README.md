## Current catalog

The following files are generated by `scripts/repo_inventory.py` using `configs/repo_inventory.json`:

- [`catalog/DOCUMENT_CATALOG.csv`](catalog/DOCUMENT_CATALOG.csv) — current indexed research documents and evidence files, excluding the inventory's own control/output paths
- [`catalog/DOCUMENT_LINEAGE.csv`](catalog/DOCUMENT_LINEAGE.csv) — explicit references and filename-based lineage candidates
- [`catalog/CANONICAL_MAP.md`](catalog/CANONICAL_MAP.md) — approved seeds and families requiring review
- [`catalog/CATALOG_ISSUES.md`](catalog/CATALOG_ISSUES.md) — broken links, root sprawl, ambiguous versions, and run-record gaps
- [`../phases/RUN_CATALOG.csv`](../phases/RUN_CATALOG.csv) — phase run directories and tracked receipt coverage

Regenerate them in Docker:

```bash
docker compose run --rm dev \
  python scripts/repo_inventory.py \
  --config configs/repo_inventory.json
```

Generated `_candidate` values are not scientific or document-governance decisions. Canonical status remains human-approved.

## Path migration rule

Use the owner paths under `research/`, `experiments/`, and `archive/` for new links. Frozen manifests and run receipts may retain historical paths; the migration CSVs under `catalog/migrations/` resolve those references. Four hash-bound scientific inputs retain byte-identical compatibility mirrors at their former paths.
