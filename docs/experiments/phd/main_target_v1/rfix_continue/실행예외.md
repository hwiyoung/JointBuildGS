# 실행 예외 기록

scientific_verdict: null

- 입력항 확장 검사의 첫 상태는 완료했으나, 두 번째 상태의 과거 명령이 `rfix_gradient.py`를 쓴 탓에 실행기가 `rfix_gradient_fast.py`라는 경로를 찾지 못했다. 이 시점에 두 번째 상태 계산은 시작되지 않았다. 두 경로를 모두 식별하도록 실행기만 고쳤고, 이미 통과한 상태를 보존한 채 나머지 검사를 이어 갔다. 학습 과정과 기준에는 변경이 없다.

- 속도 후보 단위 점검의 첫 준비에서 해시 확인 파일명에 `speed`가 빠져 계산 전에 종료되었다. 후보 바이너리 이름을 바로잡고 `units_r2`의 새 경로에서 재검사한다. 실패 로그는 보존했다.

## 15,000회 이후 CPU 사전 점검

첫 합성 점검은 NaN을 넣는 시험 코드의 스칼라 인덱싱 오류로 실패했다. 학습 코드·설정·기존 잠금은 그대로 두고 r2 시험만 별도 기록했다. r2에서 원래 건강 함수의 NaN STOP JSON 직렬화 예외가 확인되어, r3은 두 판의 실제 동일 예외를 비교했다. 10개 비교 모두 통과했다. 실패 로그와 각 시험 코드·시각·해시는 attempt2/execution에 보존했다.

## GPU 대기 작업 이동

15,000회 이후 이어 학습이 새로 승인되어 GPU 1을 학습에 배정했다. 아직 Docker 실행·계산을 시작하지 않고 GPU 1 임대를 기다리던 속도 후보 `r7_LoD2_30000` 런처만 종료하고, 남은 읽기 전용 검증을 GPU 0 대기열로 옮겼다. 완료된 계산은 재실행하지 않았다. 기존 대기열의 비정상 종료는 이 운영상 취소이며 학습·수치 검증 실패가 아니다. PID·시각·명령은 `rfix_speed/execution/gpu_reschedule.json`에 있다.

## 15,000회 보고서 작성

독립 채점 검산의 상태 이름은 `PASS_INDEPENDENT_SAVED_ARITHMETIC`이다. 첫 집계 대기줄의 `PASS` 완전 일치 검사만 실패했고, r2 대기줄은 같은 통과 상태를 받아 보고서 작성을 시작했다. 채점과 검산은 모두 완료됐다.

그림 작성에서 `0020` 접미사만으로 영상을 찾으면 다른 비행 시각의 0020이 먼저 잡혔다. 해당 저장 파일이 없어 보고서 작성이 멈췄다. 기존 렌더 단계에 이미 고정된 정확한 두 영상 이름(20241217102535_0020, 20241217091133_0109)으로 경로를 고쳤다. 부분 보고서와 이전 코드는 `rfix_continue/report_failures/15k_camera_lookup_v1`에 보존했다. 학습·채점값·그림 시점은 바꾸지 않았다.

## 속도 후보 최대 차 행 순위 보강

기존 기울기 요약은 65,536행마다 큰 차 8개, 매개변수마다 최종 16개만 남겼다. 8개 상태의 상대 L2 기준은 모두 통과했으나, 속도 후보의 r8 LoD2 중단 상태와 GeoGS LoD2에서는 이 요약만으로 최대 차 20개 행의 소속을 증명할 수 없었다. 과거 검사·입력항 결과를 보존하고 두 상태의 같은 30장·같은 손실로 순위를 다시 기록한다. 새 기록은 조각마다 65개를 남겨 전역 64개와 첫 제외 행을 정확히 구하며, 동률은 행 번호 순으로 처리한다. 잠금 설정은 rfix_speed_rank_full.json이다. 학습·허용 기준·그림 시점은 변경하지 않는다.

## 30,000회 교차표 행 대응

첫 교차표는 진단 스냅샷과 렌더 PLY의 전체 좌표 바이트 일치 검사에서 멈췄다. r22 train.py 1165행의 스냅샷 뒤 1314행에서 폭 묶기를 한 번 더 하고, 1317행에서 완전 체크포인트와 PLY를 저장한다. CPU 검산 결과 12개 패치 가우시안만 최대 0.0000019073486328125 m 달랐다. 렌더 좌표는 완전 체크포인트 좌표와 정확히 같고, 모든 init_id·origin·목표 꼬리표와 관련 메타데이터는 스냅샷과 정확히 같았다. 풀림 출신의 좌표는 모두 정확히 같았다. 따라서 교차표 r2는 완전 상태의 메타데이터를 연결하고 풀림 좌표의 정확한 일치를 다시 검사한다. 모델·스냅샷·학습 코드는 고치지 않았다. 첫 실패와 입력 잠금은 보존했다.

첫 CPU 행 대응 진단은 저장 Parameter를 numpy로 바꿀 때 detach가 필요해 종료됐다. r2 진단만 따로 잠그고 실행해 검산을 통과했다.
