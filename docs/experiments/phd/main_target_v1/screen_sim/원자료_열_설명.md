# 원자료 열 설명

외부 위치는 전달 묶음의 `external_payloads.json`에 적었다. 가우시안 행 번호는 해당 상태의 원본 PLY 행 번호다. 상태끼리 같은 행 번호를 같은 가우시안으로 해석하지 않는다.

| 파일 / 열 | 뜻과 단위 |
|---|---|
| `states/<상태>/radii/<영상>.npz : radius` | 원래 forward가 반환한 각 행의 화면 반지름, 정수 px. 203장 모두 저장 |
| `gaussians.npz : xyz` | 저장된 중심의 모델 지역 좌표, m. EPSG:25832 XY에서 기존 작업 원점을 뺀 좌표 |
| `max_radius` | 203장 반지름 최댓값, px |
| `max_radius_view` | 잠금 설정 `views`의 0부터 시작하는 영상 번호. 동률은 먼저 나온 영상. 모두 0이면 −1 |
| `max_radius_over_width` | 영상마다 `radius / width`를 계산한 뒤 그 최댓값 |
| `total_contribution` | 모든 영상·화소의 실제 채택된 `alpha × T` 합. RGB 색값을 곱한 값이 아님 |
| `roi_contribution` | 동일한 합을 공통 MVS 평가 화소에 한정한 값 |
| `max_contribution` | 모든 영상·화소 가운데 해당 행의 단일 `alpha × T` 최댓값 |
| `<후보>_remove.npy` | 원본 행을 제외하면 참인 불리언 배열. 네 후보는 각각 원본에서 독립적으로 제외 |
| `groups.npz : xy, height` | 이전 원인 점검의 가로·높이 4칸 번호, 각각 0~3 |
| `tag, provenance_names` | 출신 번호와 해당 상태의 이름 목록. GeoGS 확인 불가를 SfM으로 추정하지 않음 |
| `nearest_camera_distance_m, near30` | 가장 가까운 학습 카메라 중심까지 3차원 거리, m 및 ≤30 m 여부 |
| `<후보>/renders/<영상>.npz : depth` | 원래 expected surface depth, 카메라 깊이 m. 이후 현재 메시의 동일 상자 마스크를 적용 |
| `rgb` | 메시 색 저장용으로 [0,1] float 렌더에 255를 곱해 uint8로 바꾼 값. 품질 점수는 이 정수 영상으로 계산하지 않음 |
| `<고정 영상>_float.npz : rgb, gt, alpha` | 비교 그림·검산용 원래 float 렌더, 학습 RGB, 렌더 알파 |
| `<후보>/summary.json : views` | 203장 각각의 겹침, 실제 정렬 버퍼 바이트, float RGB 품질, 관측 메모리·시간 |

원시 AXES `values.json`의 기존 `mean` 열은 **cm**다. 전달용 `axes71.csv/json/md`의 `GT_mean_distance_m`, `result_E_mean_distance_m`는 **m**로 변환했다. R·P·뜬 면·면 없음 열은 0~1 비율이며, 보고서의 변화량은 %p다. PSNR 변화량은 dB다.

`area_m2`는 해당 칸에서 채점 가능한 패치 넓이이고 `unscorable_area_m2`는 별도로 셀 수 없는 넓이다. `n_result_E`가 사용자가 요청한 셈 마의 결과 점 수다. `n_result_all`과 `excluded_result_E`를 함께 적어 제외 수를 확인할 수 있게 했다. 열두 칸과 합계 세 줄은 중복 없는 열다섯 칸이 아니다.

과거 누적 화면 반지름 기록을 복원한 자료가 아니다. **이 저장 상태를 고정하고 203장을 다시 그려** 구한 반지름과 기여다. 미래 학습 중의 정리 결과를 대신하는 자료로 표시하지 않는다.

GeoGS의 실제 `sparse_lod` 카메라는 텍스트 표현이다. 처음 잠근 대응 이진 카메라와 학습 영상 203장의 자세·내부표정 수치를 비교해 두 사전 정보 모두 최대 차이 0을 확인했다. 파일 형식의 바이트 동일성을 주장하지 않는다. 원 파일 경로·해시와 비교값은 [카메라 연결 검산](tables/geogs_camera_binding.json)에 있다.
