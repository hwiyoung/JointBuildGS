## 소스 조회 예외

- SuGaR arXiv v5 HTML 조회는 서비스 내부 오류를 반환했다. arXiv abstract와 저자
  프로젝트 설명 `https://anttwo.github.io/sugar/`를 확인했다. 원문을 읽지 못한 부분을
  구현 사실이나 성능 비교로 주장하지 않는다.
- 초기 파일 조회에서 존재하지 않는 `b_prepare.py`, `b_corrected_run_docker.sh` 및
  작성 중이던 `joint_error.py`를 조회했다. 파일 목록과 실제 새 드라이버를 확인해 해결했다.
  이 조회 실패는 연구 실행 실패나 데이터 결손이 아니다.

## 연구 구현의 적용 한계

- A의 선형 joint-error 검산은 알려진 synthetic 모형에서 수행한다. 실제 P2 source 오류와
  영상 의존성 모형의 보정이 없으므로 실지역의 적격성·오채택률을 산출한 것으로 쓰지 않는다.
  LP 결과는 부동소수점 수치해이며 연속 3D의 엄밀 구간 인증이 아니다.
- B의 첫 잔차 가중 probe는 고정 기하·SH0에서 외관 학습만 비교했다. 추가로 같은 초기
  기하의 SH3 표현 확장을 별도 실행했다. surface 결합·면 세분·세부 이동을 실행한 것으로
  쓰지 않는다. SH0의 초기 MAE 악화와 가중치의 지표별 교환관계도 그대로 남긴다.
- A→B 연결 fixture는 실제 두 native source를 사용하지만 선택표는 코드 연결 확인용이다.
  실제 A가 선택했다고 해석하거나 별도 B 진단과 합쳐 통합 방법 성능으로 보고하지 않는다.

개별 A/B 실행 중 발생한 실패와 조치는 각 계산 명세와 외부 실행 기록에도 남긴다.

## A 진단 기록의 구분 보강

첫 합성 실행 v1의 truth 포함 진단은 생성 latent 전체의 포함성을 뜻했다. 관측하지 않은
source의 오류 변수까지 포함하므로 현재 위치 x의 가능성과 혼동될 수 있었다.
전체 latent와 현재 x의 가능성을 별도로 기록한 v2를 추가했다. 판단 알고리즘·9개 조건·
54개 판단은 동일하며 v1을 보존했다. 실제 P2 오차 보정이나 성능 결과의 수정이 아니다.
