## 2. 현재 합의한 첫 방법 후보

사용자는 prior–영상 depth 차이를 국소 가중의 입력으로 사용하는 데 동의했고, prior에서 시작하는 refinement에서 `(1-a_p,a_p)` 상보 가중을 먼저 검토하기를 선호한다. 독립 영상 가중 b를 필수로 두지 않는다.

두 target이 같은 ray·depth 정의·단위에서 유효한 영역 Omega에서:

\[
\Delta_p=|D_{P,p}-D_{V,p}|,\qquad
a_p=g(\Delta_p)=\operatorname{clip}\left(\frac{\Delta_p-\tau_0}{\tau_1-\tau_0},0,1\right),\quad 0\le\tau_0<\tau_1,
\]
\[
L_D=\frac{1}{|\Omega|}\sum_{p\in\Omega}
\left[\lambda_P(1-a_p)\rho(\hat D_p-D_{P,p})+
\lambda_Va_p\rho(\hat D_p-D_{V,p})\right].
\]

lambda는 전체 픽셀에 공통인 기준 강도이고 a_p는 픽셀별 배율이다. 픽셀별 잔차에 가중을 곱한 뒤 평균낸다. 그래프에서 쓴 0.5m·2m는 설명용 수치이며 실험 문턱·권장값으로 확정하지 않았다. 현재 후보의 g는 특정 논문에서 직접 가져온 검증 규칙이 아니라 사용자 제안을 구체화한 비교 방법이다.

- 두 target을 고정하면 a는 정적 공간 맵이다. rendered–영상 잔차는 실제 수정 경과를 읽는 지표로 사용하며, 우선 a의 입력으로 계속 갱신하지 않는다.
- 큰 Delta는 두 감독의 충돌이며 영상이 더 정확하다는 보증이 아니다. 같은 Delta에서 반대 동작이 필요한 경우를 평가한다.
- lambda_P와 lambda_V가 다르면 a=0.5도 최종 두 계수의 동등함을 뜻하지 않는다. 공간 배분과 전체 감독 강도 변화가 함께 생길 수 있다.
- prior만/영상만 유효한 픽셀은 해당 source의 유효 감독을 사용하도록 결손 규칙을 따로 정한다. 결손을 Delta=0이나 임의의 큰 Delta로 치환하지 않는다.
- 두 target이 같고 a=0이면 같은 깊이를 prior 항이 계속 감독한다. 영상 depth 항과 RGB 항은 구별한다.
- a를 loss 계수로 쓰는 것과 Gaussian의 위치·방향·크기·생성·삭제를 제한하는 것은 다른 제어다.

## 3. 출발점과 첫 실험 질문

**지역별 기존 complete Anchor8k를 그대로 재사용하고, 동일 상태에서 기존 refinement와 새 상보 가중 refinement를 분기한다.** 기존 최종30k 결과에서 새로 시작하거나 Anchor를 다시 학습하는 비교가 아니다. 기존 계보에 맞추면 8k 이후 22k refinement가 비교 후보이며 실제 자원·일정은 계획에서 확정한다.

첫 질문은 이 초기 상태에서 국소 가중이 기존 제어보다 필요한 수정과 유효 구조 보존을 개선하는가이다. Anchor 자체의 필요성·최적성·손실된 모든 세부의 복구 가능성을 검정하는 비교는 아니다.

같은 Anchor는 PLY만 같은 것이 아니라 모델·optimizer·보호 mask/hook·controller·RNG·카메라 순서와 잔여 stack 등 complete state를 공유한다는 뜻이다. 복원 후 의도한 제어만 바꾸며 기존 snapshot은 보존한다. 정확한 payload 경로·hash는 아래 resolver와 실행 영수증으로 다음 계획에서 결박한다. 이번 인계에서 대용량 checkpoint를 새로 로딩하거나 재해시하지 않았다.

## 4. 구조 보호는 독립 요인으로 비교

첫 비교에서는 기존 native 보호를 유지하여 loss 변경의 효과를 읽는다. 동시에 보호 해제의 대응 쌍도 계획에 포함한다. 최종 방법에서 native 보호를 영구 유지하거나 제거할지는 아직 결정하지 않는다.

| refinement 감독 제어 | 기존 보호 native | 기존 보호 해제 release |
|---|---|---|
| 기존 제어 G | G,N — 기존 결과 재사용 적합성 검토 | G,R — 같은 전역 설정의 기존 결과 재사용 적합성 검토 |
| 새 상보 국소 가중 L | L,N — 새 계획 후보 | L,R — 새 계획 후보 |

- L,N vs G,N: 기존 보호 아래에서 새 가중의 효과.
- L,R vs G,R: 보호가 해제된 조건에서 새 가중의 효과.
- 같은 제어의 N vs R: 보호 유지가 손상을 줄이는지, 필요한 수정을 제한하는지.
- 위 두 가중 효과의 차이: 새 가중의 효과가 보호 상태에 얼마나 의존하는지. 비선형 최적화의 상호작용을 측정하며 완전한 원인 입증으로 확대하지 않는다.

실행 순서는 native 쌍부터 검토할 수 있지만 release를 native 실패 때만 사후 추가하는 방식으로 계획하지 않는다. native에서 성공해도 기존 보호에 의존한 성공인지 확인할 질문이 남는다. 자원상 release를 생략하면 보호의 필요성·상호작용은 미확인으로 표시한다.

기존 release는 위치·회전·크기의 gradient 감쇠와 보호 Gaussian의 clone/split/prune 제외를 함께 해제하는 묶음이다. 다른 densification·opacity 규칙, prior 초기화와 Anchor는 남는다. 따라서 release는 image-only 조건이나 모든 정규화 제거가 아니다. 2×2는 우선 이 보호 묶음의 효과를 검토하며 개별 보호 구성요소의 원인까지 분리하지 못한다. 필요성이 확인될 때만 세분화한다.

Prior depth 항을 약화해도 보호가 남으면 해당 Gaussian의 기하 수정이 제한될 수 있다. 반대로 보호를 풀면 필요한 수정과 유효 구조 손상이 함께 늘 수 있다. 두 가능성 모두 검증할 가설이다. gradient 배율 0.01을 Adam의 실제 변위 1/100로 해석하지 않는다.

### 4.1 기존6조건과 비교표4칸, 신규 실행 수

기존6조건은 지역마다 `prior 전역 깊이 계수3수준(.005/.0005/0) × 보호2상태(native/release)`다. P1/P2/P3의 세 지역 전체에서는 기존 주18개 실행이다.

이번 표4칸은 **하나의 비교 전역 설정에서 기존/국소 감독 제어2종 × 보호2상태**를 뜻한다. 기존6조건 각각에 다시4조건을 곱하는 계획이 아니다. 기존6조건은 전역 조정의 충분성을 확인하는 대조 자료로 보존하고, 그중 설정이 맞는 두 보호 조건을 표의 기존 제어 행에 연결한다.

| 구분 | 지역당 조건 수 | P1/P2/P3 전체 | 해석 |
|---|---:|---:|---|
| 완료된 기존 전역 제어 | 6 | 18 | 세 prior 계수와 두 보호 상태의 기존 결과 |
| 표4칸 중 기존 제어 행 | 2 | 6 | 위 기존 결과에서 재사용 적합성을 확인할 일부이며 추가 실행 수가 아님 |
| 표4칸 중 새 상보 가중 행 | 2 | 6 | 하나의 g·lambda 설정에서 보호 유지/해제를 추가하는 최소 신규 후보 |

따라서 **하나의 문턱쌍과 전역 설정, 반복1회, 기존 대조군 재사용 가능**을 가정하면 신규 refinement는 지역당2개, 세 지역 합계6개다. 이는 현재 비교 구조의 산술 예시이며 확정한 실행 예산이 아니다. 문턱쌍·전역 계수·반복 수를 늘리거나 동일 일정의 대조군을 새로 실행해야 하면 그만큼 추가된다. 서로 다른 g/lambda 후보 K개를 두 보호 상태에서 모두 시험하면 신규 국소 가중 실행은 지역당2K개이며 대조군 보완·반복은 별도다.

`prior O/X × 영상 O/X` 네 분류는 위 표4칸과도 다르다. 하나의 결과에서 영역별로 보존·수정을 평가하는 기본 분류이며, 그것만으로 네 배의 학습 실행을 만드는 것은 아니다. 별도 오염 통제 데이터를 생성하는 실험은 추후 다른 계획으로 구분한다.

## 5. 기존 P1/P2/P3의 재사용 조건

완료된 기존 조건은 지역별 prior 깊이 `.005/.0005/0` × 보호 `native/release`의 6조건이다. 과거 실행은 대조 근거로 재사용하되, 임의의 한 원설정만 비교하여 충분히 조정한 전역 제어보다 우수하다고 주장하지 않는다. `.0005`와 `0` 등 기존 전역 제어의 성공도 검토한다. GT로 지역별 최적 설정을 골라 배포 가능한 알고리즘인 것처럼 제시하지 않는다.

다음 두 비교 목표를 반드시 구별한다.

1. **기존 controller를 그대로 사용한 전체 변경 효과:** 양쪽에 동일 controller 정책을 적용하지만 실제 lambda_V(t)는 다른 학습 경과 때문에 달라질 수 있다. 그 반응까지 포함한 전체 효과다.
2. **국소 가중 규칙의 효과를 분리한 비교:** 같은 lambda_V(t) 궤적을 공통으로 고정하거나 재생한다. 이는 별도의 통제 조건이다. 과거 실행이 그 궤적과 다르면 동일 대조군으로 대체할 수 없다.

실제 `CONTROL_TRAJECTORIES_ko_v1.md`에서 일부 조건의 DA3 가중은 .05에서 .0475 등으로 변했고 P3 `.005 native`는 기록상 .04286875까지 내려갔다. 모든 기존 run이 .05 고정이라고 쓰지 않는다. 다음 세션에서 먼저 위 비교 목표와 전역 일정 정책을 정한다.

입력 품질과 감독 제어를 구별하기 위해 첫 비교의 DA3 bytes는 그대로 둔다. ACMP 등 target 교체는 별도 질문이다. 국소 가중이 유리할 경우, 그 이득이 공간 배분 때문인지 평균 감독 강도 변화만으로 설명되는지 구별할 전역 계수 대조도 계획한다. 가중 합으로 loss를 재정규화할지 여부는 감쇠 효과를 바꾸므로 명시한다.

기존 P2/P3 원설정의 연속 실행과 변경 조건의 재개 실행, 복원 직후 일치 확인과 장기 CUDA 궤적·반복 변동 미확보를 구분한다. 작은 차이의 재현성을 주장하려면 해당 검증이 필요하다. 과거 OOM·미실행 반복은 성공 결과로 채우지 않는다.

## 6. 평가와 기각·축소 조건

- prior O/X × 영상 O/X 네 분류를 평가의 기본 틀로 유지한다. 결손·관측 부족·정합·가림·같은 영역의 혼합 조건은 그 안에서 세분화한다. 평가 GT 분류를 가중 계산에 넣지 않는다.
- 같은 ROI·같은 지지 범위에서 필요한 수정과 처음 유효했던 구조의 손상을 함께 보고한다. prior 유효성과 Anchor-near는 같은 정의가 아니다.
- 정확도·완전성·현재성·관측 가능한 세부·외관·계산량을 구별한다. 기존 공간 진단의 UAS점 조건부 근접률을 면적 보존율·F1로 바꾸어 부르지 않는다.
- rendered expected depth, Gaussian 중심, 추출 mesh를 구별한다. 같은 해상도·추출 설정의 raw 표면을 비교하고 기존1024 결과와 같은 Anchor512 기반 진단을 혼합하지 않는다.
- 기존 전역 조정으로 충분하면 새 국소 제어의 필요성을 축소한다. 개선이 구조 보호 해제만으로 설명되면 가중 규칙의 증분 기여를 주장하지 않는다.
- 같은 손상 수준에서 수정이 늘거나 같은 수정 수준에서 손상이 줄지 않으면 유효 보존·수정의 개선 가설을 기각·축소한다. 가중 제어가 외관만 개선하면 기하 개선과 분리한다.
- native에서 효과가 없고 release에서만 효과가 있으면 보호와의 상호작용을 조사한다. 이를 곧바로 보호가 유일한 원인이라고 단정하지 않는다.
- 두 target이 모두 틀리거나 정보가 부족한 조건은 이 가중 규칙의 한계로 남을 수 있다. 문턱 조정만으로 해결할 수 있다고 가정하지 않는다.

## 8. 읽기 순서와 정확한 자료 위치

**아래 파일을 모두 최신 방법 설계로 다시 쓴 상태는 아니다.** 최신 합의, 이전 탐색 후보, 기존 실행 사실, 역사 계약을 함께 연결한 목록이다. 새 설계에는 이 인계와 현재 상보 가중 설명을 우선하고, 과거 실행의 사실은 해당 영수증·정정 자료에 따른다. 각 문서의 역할은 다음과 같다.

| 문서 묶음 | 현재 역할·정리 상태 | 새 세션에서의 적용 |
|---|---|---|
| 이 인계 문서, `LOCAL_COMPLEMENTARY_WEIGHTING_EXPLAINER_ko_v1.md` | 최신 논의 반영 | prior–영상 차이, 상보형 첫 후보, 같은 Anchor, 보호 독립 비교를 출발점으로 사용 |
| `WEIGHT_FUNCTION_DESIGN_AND_RESIDUAL_ROLES_ko_v1.md` | 함수 근거·잔차 역할과 이전 a,b 후보를 보존 | 독립 b 우선 비교 제안은 이전 검토안. 현재 첫 후보는 b=a이며 문턱·전역 계수는 미확정 |
| `CONTROL_TRAJECTORIES_ko_v1.md`, `DA3_REFINEMENT_SPATIAL_RESULTS_ko_v1.md`, `DA3_AUDIT_INTERPRETATION_CORRECTION_ko_v1.md` | 기존 실행의 관측·공간 진단·해석 정정 | 새 가중의 실행 결과가 아니다. 측정 범위와 정정을 함께 읽음 |

## 9. 이번 인계 작업의 확인 범위

문서·기존 config·실현 제어 기록을 읽고 별도 인계 파일만 작성했다. 소스·기존 산출물·진행 작업·서비스는 변경하지 않았다. 경로 확인 중 존재하지 않는 `RESULTS_ko_v1.md`와 causal_followup 아래의 `CONTROL_TRAJECTORIES_ko_v1.md`를 조회한 오류가 있었으며, 파일 목록을 통해 위의 실제 경로로 정정했다. 프로젝트 계산·새 실험은 수행하지 않았다.

사용자의 후속 확인에 따라 이 인계 파일에 문서 역할과 최신 합의의 우선순위, 현재 세션 실행 제한의 직접 출처, 다음 세션 사용자 요청의 범위, 비교 셀과 신규 실행 수를 보완했다. 기존 문서·config·결과는 소급 변경하지 않았다.
