# MVS 점군 표시 v1.2 점검 기록

- 기존 v1.1은 MVS 수치도 사전 패치/LoD2 면에 칠했다. 사용자 요청으로 실제 MVS 원본 XYZ에 색칠하는 보기를 기본으로 추가했다. 각 칸의 형상·값 이름을 분리했다.
- 6.1의 구간 경계에 별도 통계적 도출 근거가 문서화되어 있지 않음을 확인했다. 계산 구간을 임의로 바꾸지 않고 화면에 고정 요약 구간임을 설명했다. 실제 마지막 구간이 40 cm를 포함하므로 ‘40 초과’를 ‘40 이상’으로 고쳤다.
- 오른쪽 층을 변경했을 때 오른쪽 3D 보기의 형상이 즉시 갱신되지 않을 수 있던 기존 이벤트 처리를 수정했다. 오른쪽 MVS→사전 정보 전환을 실제 DOM 이벤트로 확인했다.
- 표시용 MVS 점을 솎았기 때문에 모든 패치가 화면의 점에 연결되는 것은 아니다. 연결 여부나 표시 점 수를 통계의 표본 조건으로 사용하지 않는다. 원래 안쪽 원·면 띠 조건 안에서만 색을 연결하며, 연결되지 않은 점에는 수치를 부여하지 않는다.
- 모든 고리 크기에서 MVS 면 위치 o가 동일한지 24개 조합으로 확인했다. 따라서 원본 1 m 파일의 o로 만든 화면 연결을 고리 선택에 재사용해도 같은 면 띠를 사용한다.
- Windows/Codex 앱 자체는 이 서버에서 제어할 수 없다. CPU Linux Chromium에서 화면·입력·오프라인 자료·전송을 검증한다. 기존 Codex 앱 다운로드 완료 문제는 서버의 전체 전송 완료와 별도로 기록되어 있으며, 외부 Chrome/Edge 직접 URL 접근을 안내한다.

## 2026-10-23: R1의 약 3 m 값과 GT 층 대응

사용자의 3 m 오차 질문에 대해 원본 GT 점과 LoD2 패치 중심·법선을 읽기 전용 Docker 계산으로 확인했다. 기존 수치·설정·웹 배포는 변경하지 않았다.

- 지붕 면 L22, 패치 82749의 기둥에는 GT 586점이 있다. prior ±20 cm 안의 409점 중앙값은 +0.042393 m다. 그러나 바깥부터 찾는 20% 규칙이 +3.0~3.3 m의 118점(118 ≥ 117.2)을 먼저 채택하고, 그 층 중심 ±1 m의 162점 중앙값 +3.127643 m를 `gt_p`와 `eL`로 기록한다. 이 숫자를 같은 지붕 면의 확정된 3.13 m 오차로 해석할 수 없다.
- 벽 면 L33, 패치 107801에서도 가까운 145점 중앙값 +0.246856 m를 두고, 검색 상한 +3 m 쪽의 44점 중앙값 +2.988931 m가 선택된다.
- 평가 범위 안에서 eL이 2.8~3.2 m인 지붕꼴 패치 611개를 모두 다시 검색했다. 351개는 prior ±20 cm 안에도 GT가 10점 이상 있고, 66개는 그 가까운 점이 기둥 전체의 과반이다. 가까운 GT의 존재만으로 그 점이 올바른 동일 면 대응이라고 확정하거나, 351개 모두를 오류로 판정하지 않는다.
- 실제 큰 거리도 관측된다. L3 패치 7212는 검색 기둥 GT 1,325점 전체가 -2.97~-2.62 m에 있고 중앙값은 -2.808791 m다. 따라서 모든 큰 값을 한 원인으로 설명하지 않는다. L26 패치 101627의 법선선에는 다른 LoD2 면 L23도 +2.374791 m에서 교차하여, 서로 겹친 단의 대응 문제도 확인 대상이다.
- 표시 이름 ‘실제 오차’는 동일 면 대응의 타당성까지 보증하지 않는다. 현재 발주문의 바깥층 우선 규칙으로 계산한 위치 차이다. 같은 면에 대한 오차로 해석하려면 다층·다른 면과의 겹침·GT 최종 법선 차이를 구분해야 한다. 가까운 층을 무조건 선택하는 변경 역시 실제 구조 변화를 숨길 수 있으므로 이 점검에서는 계산 규칙을 바꾸지 않았다.
