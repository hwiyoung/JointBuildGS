# 객체 방향 R1–R5 영상·MVS 감독 지원 감사

- Task: `PHD-R1R5-VIEW-SUPPORT-v1`
- 승인: 사용자가 5개 객체 정렬 사각형을 향후 작업 기준으로 채택하고 영상 수와 주 기여 영상 수 확인을 요청함.
- 범위: 좌표 기준 v1 정의, 기존 exact-937 카메라/RGB/MVS depth의 입력 지원 집계. 새 학습·MVS 생성·참조 평가 없음.
- `scientific_verdict: null`

## 영역

그림의 사각형은 개략 선정안이다. 생성 이미지의 픽셀을 측량 좌표로 사용하지 않고, 앞서 원 MVS에서 확인한 건물 축을 따라 70도(Easting에서 반시계)의 u축과 시계방향 직교 v축으로 수치화한다. 기존 P1/P3는 R1, P2는 R2 안에 전부 포함한다. R2는 기존 P2 prism XY까지 포함하도록 문맥을 조금 넓힌다. 인접 문맥의 중복을 보존하고 면적/영상 수를 독립 표본 수로 합산하지 않는다. 기계 판독 정본은 `configs/phd/region_view_support_v1/regions_v1.json`이다.

## 주 기여의 의미

1. 후보 영상: 영역의 동일 MVS 표본 중 max(10개, 1%)를 프레임에 포함하거나 native MVS 100픽셀 이상이 영역 안에 역투영되는 카메라. 투영 가능은 실제 관측 보장이 아니다.
2. 학습/평가 **후보**: 위 목록을 정확한 파일명으로 정렬하여 기존 llffhold=8 규칙 적용. 기존 재구성의 평가 영상 참여 및 지역 간 중복 때문에 독립 test가 아니다.
3. 유효 감독 영상: 양수·유한 native MVS가 영역에 존재. 1/100/1000픽셀의 민감도 수를 모두 제시한다.
4. 주 기여 영상 수: 원 RGB 정수 ray→native K→nearest 깊이 조회를 따른다. 영상별 `영역 내 유효 RGB depth 픽셀 수 / 그 영상 전체 유효 RGB depth 픽셀 수`를 동일 카메라 선택 빈도하에서 합산한다. 누적 50/80/90%를 차지하는 최소 영상 수, 최대 1장 비중, 상위 목록을 제시한다.
5. 위 4는 유효 감독 **계수량**이며 실제 loss 잔차·gradient·정확성·독립 관측 수가 아니다. finite render depth, 동일 scalar weight, 추가 mask 없음이라는 가정이 있다. 향후 마스크나 동적 가중치를 변경하면 재집계한다.

## 국소 편중

영역 전체와 기존 P1/P2/P3 core를 나눠 집계한다. 5m×5m×2m 국소 voxel에서 영상별 RGB 감독량과 한 장 우세 여부를 기록한다. 추가로 같은 fused-MVS 표면 좌표를 각 native depth에 조회하여 0.25/0.5/1m camera-Z 일치 영상 수를 산출한다. 입력끼리의 일치이며 UAS 정확도 평가가 아니다.

P1 수동 보정 지면은 기존 `0100_D` 기준 표본을 별도로 조회한다. 원 감사의 98뷰와 새 R1 후보 및 전체937뷰 결과를 분리한다. 기존 기록은 0100_D가 수동 R1 native 표본의 77.84%를 차지했다는 뜻이며, 전체 loss에 한 장만 참여했다고 확정한 결과가 아니다.

## 재현 및 검증

Docker CPU 제한 실행, exact 카메라·crosswalk·fused 입력 해시 확인, 실제 사용하는 depth/RGB 해시 기록, 코드/config/commit/image ID 보존. 기존 P1 bindings의 K/R/t/depth hash와 역투영·resampling을 대조한다. 자기 시점 지면 투영, 회전 좌표 왕복, loss 분모가 다른 두 뷰의 계수량을 검증한다. 결과 CSV/NPZ의 집계와 요약을 다시 대조한다.
