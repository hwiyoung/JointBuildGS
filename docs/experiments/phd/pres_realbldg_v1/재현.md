# 계산과 파일

이 결과는 저장된 지붕·벽 경우의 건물별 집계다. 바닥 경우가 없으므로 ③나는 벽으로만 계산했다. 바닥을 포함한 전체 공간 범위의 다섯 조건 충족 여부는 확인 불가다. 사진 수를 구하지 않은 벽은 0으로 채우지 않았다. 건물을 선택하거나 과학적 결론을 내리지 않았다.

설정은 `configs/phd/pres_realbldg_v1/realbldg_v1.json`, 최초 시각과 SHA-256은 같은 폴더의 `realbldg_v1.initial.lock.json`에 있다. 사용자 보충 수치는 `provenance/criteria_addendum1.md`에 보존했다. 최초 계산 기록은 `provenance/first_calculation.json`이다.

실행은 저장소 루트에서 `bash scripts/phd/pres_realbldg_v1/run_cpu.sh 기록이름 스크립트.py 인자` 형식으로 수행했다. `jointbuildgs:dev`의 실제 이미지 ID, Python과 라이브러리 버전은 `provenance/runtime.json`, `provenance/delivery_audit.json`에 있다. 컨테이너 하나당 CPU 8개·메모리 32 GiB, 동시 CPU 최대 24개를 사용했다. GPU 장치와 네트워크는 연결하지 않았다. 입력 저장소와 앞 작업은 읽기 전용이다.

계산 순서는 다음과 같다. 이미 존재하는 중간 파일은 재사용한다. 입력이 바뀐 재실행은 이 봉인본과 별개의 작업이다.

1. `preflight.py`: 최초 설정 잠금, 입력 목록과 사진·카메라 파일 확인.
2. `prepare.py`: 기존 경우와 RECOUNT 소속을 읽어 작업 전용 배열 생성.
3. `zones.py 장면`: 처마선 거리와 지붕·벽 범위. 장면은 세 실험 지역 × LoD2·ALS 및 `outside__LoD2`, `outside__ALS`의 여덟 개다.
4. `photos.py`: 저장된 같은 점의 무늬 값을 재사용하고 필요한 점만 학습 사진에서 구함.
5. `measure.py 장면`: ① 지붕, ②, ③가, ③나의 넓이와 길이.
6. `visibility.py LoD2장면`: 선행 조건 둘 이상인 건물의 벽 사진 수. B173 주변 면 53은 별도로 포함.
7. `face53_check.py`, `finish_measure.py`: 면 53 재확인, ① 벽과 ④, 순위와 표.
8. `figures.py 건물번호`: 상위 다섯 동 각각 사진 바탕과 경사 사진, 총 열 장. `visual_qa.py`로 PNG 해독·크기·해상도와 출처 확인.
9. `verify_inputs.py`, `validate.py`, `report.py`, `delivery_audit.py`, `seal.py`: 원자료 보존, 수치 검사, 보고서, ZIP 검증.

추가 검사에서 발견한 미소속 벽 181점은 `repair_unassigned.py`로 이 작업의 배열만 수정했다. 현재 `prepare.py`에도 같은 수정을 반영했다. 건물 소속과 경우는 그대로이며 모든 건물별 넓이가 수정 전후 같다. 확인 기록은 `provenance/unassigned_projection_correction.json`이다.

PH 실제 경로는 저장소 옆 `../JointBuildGS-artifacts/phase-payloads/phd/pres_realbldg_v1/PHD-PRES-REALBLDG-v1/`이다. 핵심점·사진 수 비트 배열·중간 배열·실행 로그는 이곳에만 있다. ZIP에는 보고서, 표, 그림과 출처 JSON, 설정, 스크립트, 검증 기록을 넣었다. 확인용 건물의 핵심점 값과 상위 다섯 밖의 그림은 넣지 않았다.

`SHA256SUMS`의 경로는 ZIP 내부 기준이다. ZIP의 CRC, 모든 구성 파일 SHA-256, ZIP 자체 SHA-256을 확인했다. ZIP은 원자료를 포함하지 않으므로 독립 실행용 원자료 묶음은 아니다. 앞 작업의 경로는 출처 JSON과 입력 목록에서 확인할 수 있다.
