# 확인 기록

- 첨부문에 조건 3.1의 기준표가 없었으며 사용자가 같은 대화에서 수치와 기준을 보충했다. 보충한 기준으로 첫 계산 전에 설정을 잠근다.
- PH는 앞 작업과 같은 외부 저장소의 phase-payloads/phd로 해석한다. 저장소 루트에 PH 폴더를 만들지 않는다.
- 완전히 같은 순위는 건물 번호 오름차순으로 표시한다. ①의 넓이는 지붕과 벽의 충족 넓이 중 작은 값으로 비교한다. 항공 LiDAR의 ①은 지붕만 사용한다.
- 느슨한 값의 사진 1장 이하는 ④에 적용한다. ①의 벽 사진 2장 이상은 그대로 둔다.
- 첫 입력 확인 실행에서 inspect.py 이름이 Python 표준 모듈과 충돌했다. 계산 전에 종료됐으며 preflight.py로 바꾸었다.
- 입력 확인 중 LoD2 자료에 없는 identity_face 열 요청으로 종료됐다. 두 사전 정보에 공통인 surf 열을 확인하도록 고쳤다.
- RESCORE 일부 경로는 /out 절대 심볼릭 링크다. 읽기 전용 호환 마운트를 추가했다. 가용 메모리를 고려해 설정 상한 64 GiB보다 낮은 32 GiB로 실행한다.
- 지붕 무늬 계산에서 영상 밖 투영값의 정수 변환 경고가 있었다. 유효 투영과 영상 경계 검사를 통과한 점만 화소를 읽으며, 이 경고가 난 점은 제외한다.
- ④의 넓이는 참값의 유무로 정하지 않는다는 개별 조건에 따라 벽 패치 넓이로 센다. 벽의 참값 수와 τ 안 비율은 별도 기록한다.
- 벽 사진 수의 영상 여백 20화소와 가림 허용 거리 0.3 m는 앞 작업의 사진 선택 코드 값을 사용한다. 이번 각도 기준은 80°이며 사진 수를 10장으로 제한하지 않는다.
- 미소속 벽 참값 181점에 첫 패치의 접선이 쓰인 것을 추가 검증에서 발견했다. 가장 가까운 기존 LoD2 벽 삼각형의 패치 접선을 넓이 투영에만 쓰도록 고쳤다. 소속·경우를 바꾸지 않으며 모든 건물 넓이가 전후 같은지 확인한다.
- ②의 보조 높이 차는 가장 큰 모임에서 저장 거리의 높이 성분 중앙값으로 구한다. 원래 높이 차와 부호를 함께 기록하며 두 세부 기준에 들지 않으면 그대로 적는다.
- 벽 사진 계산을 생략한 건물의 ①·④를 0으로 채우지 않는다. 조건별 표는 확인된 충족 수와 미확인 수를 따로 싣고, 가능한 최대 충족 수로 상위 다섯의 순위 영향을 확인한다.
- 저장된 여덟 자료의 kind에는 지붕 1과 벽 2만 있고 바닥 경우는 없다. S1 rows_of의 저장 모집단은 지붕·벽으로 제한돼 있다. ③나 바깥은 저장 벽 경우로만 계산했으며 바닥 경우를 새로 만들지 않았다. 바닥을 포함한 전체 공간 범위의 다섯 조건 충족 여부는 확인 불가다.
- 2026-11-05T20:17:20.074060+09:00: 지역 밖 저장 칸 5는 사전 정보가 틀리고 영상이 없는 경우로, GTJUDGE의 다섯 경우에 맞춰 둘 다 틀림에 합쳤다. 칸 6·9는 확인 불가로 남겼다. 기존 칸 값은 바꾸지 않았다.
