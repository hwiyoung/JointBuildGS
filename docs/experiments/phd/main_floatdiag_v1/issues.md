# PHD-MAIN-FLOATDIAG-v1 issues

FD-001: ZIP에 UTF-8 이름 표시가 없어 최초 검증이 파일명 KeyError로 종료됐다. 내용 추출과 과학 계산 전에 종료됐으며, ZIP 표시에 따라 이름을 UTF-8로 복원해 SHA256SUMS와 비교하도록 수정했다. 원 로그는 외부 logs/에 보존한다.

FD-002: 연결된 worktree의 Git 메타데이터가 컨테이너에 없어 준비 영수증 생성이 종료됐다. 원래 경로에 메타데이터를 읽기 전용으로 연결하고 GIT_OPTIONAL_LOCKS=0을 적용했다. 이미 저장된 설정과 잠금 시각은 그대로 보존했다. 과학 계산과 학습은 시작하지 않았다.

FD-003: 최초 카메라 초안은 메시 직교투영과 가우시안 원근투영이 달랐다. 첫 캡처 전에 이 작업의 준비 프로세스만 종료하고, 둘 모두 같은 원근 카메라를 쓰도록 수정했다. 기존 설정·잠금과 준비 좌표는 history/와 coordinate_pre_perspective.json에 보존했다. LOSSTRAIN과 다른 서비스는 변경하지 않았다.

FD-004: R1 실사 선택 초안에서 패치 중심을 참값 면으로 옮겨 투영한 오류를 발견했다. 3.4의 원래 패치 중심으로 수정했다. 초안은 history/pre_original_centres_photos_R1rep_b10_ALS.json에 보존했다. 저장 모델, 렌더, PSNR, 사례 선택과 메시 캡처는 변경하지 않았다.

FD-005: R1 판 2 렌더 자체는 PSNR 영수증과 가상 시점 캡처를 마쳤지만, 실행 중인 Bash 파일에 출처 기록 기능을 추가하면서 Bash의 남은 파일 읽기가 어긋나 종료 코드 2를 냈다. 과학 출력의 완료 여부는 개별 영수증으로 확인하며 이 셸 오류를 숨기지 않는다. 이후 실행은 launch.py가 원문을 불변 문자열과 별도 스냅샷으로 고정한 뒤 실행한다.

FD-006: GPU 0 입장 검사가 유휴 상태의 GNOME 원격 데스크톱 CUDA 문맥도 학습 작업으로 세어 착수를 보류했다. PID와 실행 경로를 확인했고, 새 실행기는 정확히 해당 표시 서비스만 제외한다. 서비스와 GPU 프로세스를 종료하거나 변경하지 않았다.

FD-007: R1 보존 띠는 원래 패치 중심을 투영한 모든 학습 사진에서 보이는 넓이의 최댓값이 1.722286676%였다. 주 시점 90%·빗각 50%를 넘지 않아 사진 선정과 실사 구조물 확인은 확인 불가로 남긴다. 임의의 사진으로 대체하지 않는다.

FD-008: R1 판 2 보존 띠에서 분리된 TSDF 조각 때문에 quadric 축소가 목표 면 수에 도달하지 않아 GLB 4 MB 검사가 중단됐다. 원본 자른 PLY와 이미 완료한 캡처는 유지했다. 웹 사본에만 2.5/5/10/20/40 cm 순서의 정점 군집화를 적용하고 목표 20,000면·상한 22,000면을 만족하는 첫 단계를 기록한다. 정적 캡처와 수치는 줄이지 않은 원본을 사용한다. 이후 새 실행기로 중단 사례부터 재개한다.

FD-009: FD-005 때 대기 중이던 B173/B0 셸도 수정된 파일의 다른 위치를 읽어 log 변수 오류로 Docker 실행 전에 종료했다. 세 작업의 원 로그를 보존했고, 이후 모두 launch.py의 불변 셸 입력으로 다시 입장한다. 다른 작업과 서비스에는 조치하지 않았다.

FD-010: CSV의 CRLF 줄 끝이 Git 공백 검사에 걸렸다. 숫자와 행은 유지하고 LF로 정규화했으며 이후 CSV 출력도 LF로 고정했다.
