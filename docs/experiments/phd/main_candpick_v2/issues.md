# 실패와 확인 불가 기록

- B173·항공 LiDAR의 43점에서 원본 `u_prior`를 구할 수 없음. 임의 값을 넣지 않고 판 다의 두 출발을 `STOP_MISSING_CANDIDATE_SIGMA`로 멈춤. 나머지 판의 입력은 영향받지 않음. [이 발주에서 냄]
- 판 라 준비 코드에서 저장된 불투명도를 sigmoid 뒤 logit으로 되돌리자, float32에서 1로 반올림된 값이 무한대가 됨. 학습 전 단위 점검에서 검출. 원본 PLY의 유한한 logit을 직접 읽도록 수정했으며 처음 실패 기록은 `preflight/implementation_r0/`에 보존. 기존 장면 바이트와 처음 렌더 값은 유지. [이 발주에서 냄]
- gsplat 1.4의 기본 깊이는 가우시안 중심의 카메라 Z를 평균함. GeoGS 메시 코드는 광선과 원반의 교차 깊이를 평균함. 첫 깊이 구현은 v1 가시성 가중치에서 교차 깊이를 구하도록 학습 전에 잠갔으나, 이 방식의 가까운 기여 처리와 불투명도 상한 오류를 이후 원본 대조에서 확인했다. 아래 r1 수정이 주 깊이 결과에 적용된다. 원래 잠금은 보존했다. [이 발주에서 냄]

- 그림 준비에서 문자열 배열에 NumPy 최소값 연산을 적용한 오류와 컨테이너 기본 글꼴의 한글 누락을 확인했다. 문자열 정렬은 Python 최소값으로, 글꼴은 v1의 Noto Sans CJK 파일로 바꿨다. 수치 계산과 학습은 바꾸지 않았다. [이 발주에서 냄]
- 저장 곡선 float16 정밀도 때문에 옛 범위 재생에서도 항공 LiDAR 406패치(27.5324 m²), LoD2 1,326패치(82.875 m²)의 15개 판단 중 하나 이상이 기존 저장 판단과 다르다. 원래 선택값에서의 틀린 넓이 영향은 photo_precision_sensitivity 표에 별도로 보존했다. [이 발주에서 냄]
- 사진 CPU 계산의 원래 완료 기록에 실행 환경의 커밋 문자열 저장이 빠졌다. 원래 기록은 유지하고, 잠금 시각의 저장소 HEAD를 Git reflog에서 확인해 `tables/photo_execution_provenance.json`에 코드·설정 해시와 함께 기록했다. 당시 환경변수의 직접 기록은 확인 불가다. 실제 새 코드는 첫 커밋 전에 SHA-256으로 잠갔으며, 저장소 HEAD가 새 코드 전체를 포함한다는 뜻으로 사용하지 않는다. [이 발주에서 냄]
- 첫 깊이 채점에서 가까운 기여가 있는 화소 전체를 확인 불가로 처리해 대표 자리의 지도가 비었다. GeoGS 원본은 해당 기여만 제외한 뒤 계속 누적하며 불투명도 상한도 0.99이다. 원본 대조 후 별도 깊이 구현으로 고쳤다. 학습 코드는 바꾸지 않았다. 원래 설정과 28판의 첫 채점·렌더 77파일은 `revisions/depth_r0/` 및 원래 잠금 파일로 보존했다. 수정 시각·이유·코드·원본 해시는 `depth_readout_amendment_r1.json`에 고정했다. 작은 예제 4개와 실제 384화소의 독립 CPU 비교를 통과했다(최대 차이 0.0318mm). [이 발주에서 냄]
