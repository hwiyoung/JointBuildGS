## 실험 역할을 실제 연구 진행과 혼동하게 설명한 문제

- 문제: A 합성 검산과 B의 실제 P2 ALS 색 학습을 연이어 보고하면서, A가 ALS를 선택해
  변화 사례를 재구성한 것으로 읽히게 했다.
- 원인: A는 P2에 적용되지 않았고 B 드라이버가 ALS seeds를 직접 읽었다. 변화 해석이
  있는 P2에서 현재 재구성 baseline과 ALS 고정 외관 진단을 구분해 전달하지 못했다.
- 조치: 실제 입력·실행 역할을 새 A 정정문서에서 분리하고 MVS 초기화 4조건을 추가했다.
  같은 사진·평가 범위·정성 뷰어에 이전 ALS 진단까지 함께 제공했다.
- 해결 범위: 초기화의 출처와 실험 의미, 정성 비교의 누락은 수정했다. 실제 P2 A 오류
  보정·판단과 세부 기하 재구성은 여전히 미실행이다.

## 작업 도구 관련 예외

- 정성 뷰어용 새 agent spawn은 thread limit으로 거부됐다. A 정정문서를 완료한 기존
  agent에 화면 구현을 후속 배정하고 root가 평가·export·브라우저 검증을 수행했다.
- dev 컨테이너에 Node가 없어 화면 agent의 node 검사에는 `NODE_NOT_AVAILABLE`이
  기록됐다. root가 브라우저 QA용 host Node의 구문 검사와 격리 Chrome 실제 실행으로
  검증했다. 프로젝트 처리·학습·Python 검산은 Docker에서만 실행했다.
- 작성 전의 frontend 경로를 확인하면서 `rg`에 일시적인 경로 없음이 반환됐다.
  생성 후 실제 파일을 검사했으며 데이터 결손이나 학습 실패가 아니다.
- 최종 포장 첫 실행에서 저장된 실행 경로 `/workspace/JointBuildGS`와 검사 컨테이너의
  `/workspace` 마운트가 달라 파일 확인이 중단됐다. 기존 실행과 같은 경로를 사용하는
  전용 Docker 드라이버를 추가했다. 중단 시 결과 manifest는 생성되지 않았다.
