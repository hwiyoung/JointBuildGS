## 0. 한눈에

### 0.1 물음

1. 캠퍼스를 얼마나 쪼개야 경계 손해와 얕은 학습 사이의 알맞은 지점인가.
   - 잘게 쪼개면 경계가 많아진다. 경계 근처는 보이는 영상이 줄고 합칠 때 이음매가 생긴다.
   - 크게 두면 학습이 얕아진다. 같은 30,000회를 더 많은 영상과 더 넓은 땅이 나눠 쓴다.
2. 그렇게 정한 단위로 학습한 결과가 건물 단위로 학습한 결과와 같은가.

## 1. 지킬 것

2. **GPU.**

   - 한 번에 한 판만 돌린다. 앞 작업에서 멈춘 것이 모두 호스트 메모리 쪽이었기 때문이다. 앞 작업의 호스트 보호 장치와 가우시안 폭증 보호를 그대로 둔다.
3. **입력은 읽기만 한다.** 결과는 `PH/main_trainunit_v1/PHD-MAIN-TRAINUNIT-v2/` 아래에만 쓴다.
4. **폴더.** `configs/phd/main_trainunit_v1/`, `scripts/phd/main_trainunit_v1/`, `docs/experiments/phd/main_trainunit_v1/`, 위 결과 폴더, `PH/delivery/`. 이 밖에는 쓰지 않는다.
5. **커밋.** 위 폴더만 경로를 적어 커밋하고 푸시한다. 쓰지 않는 것: `git add -A`, `git add .`, `git commit -a`, `git stash`, 브랜치 바꾸기, `git reset`, `git pull`, `git rebase`.
6. **설정을 먼저 잠근다.** `configs/phd/main_trainunit_v1/trainunit_v2.json`에 판, 나누기 규칙, 영상 넣기 규칙, 건물 소속 규칙, 채점을 적고, 첫 계산 전에 저장 시각과 sha256을 남긴다.

8. **멈추면 까닭부터 확인한다.** 실행 오류나 메모리 부족으로 멈추면 3.5의 원인 확인을 먼저 한다. "메모리 부족"이라고만 적고 넘어가지 않는다.

   - 잘못이 아니면 같은 설정으로 한 번만 다시 돌린다. 그래도 멈추면 '결과 없음'과 3.5의 기록을 남기고 다음으로 간다.
9. **긴 실행은 `tmux` 또는 `nohup`으로 띄운다.** 확인 간격은 10분 이상이다.
10. **정량과 정성을 함께 낸다.** 네 경우를 늘 함께 낸다. 짐작으로 채우지 않는다. 없는 것은 '없음'이라고 적는다.

### 2.2 아홉 칸 나누기

- 앞 작업의 `tu_cells.py`를 쓴다. 바꾸는 것은 칸 수뿐이다: 3 × 3.
- 넓히기 20 %, 영상 넣기 25 %, 점과 목표 고르기, 합치기 규칙은 앞 작업과 같다.
- **기록(칸마다):** 자기 카메라 수, 학습 영상 수, SfM 점 수, 목표 패치 수, 넓힌 칸의 가로와 세로, 장면 크기에서 나오는 문턱의 실제 값.
- **건물 소속 기록:** 건물마다 윤곽 중심이 든 칸을 적는다. 넓힌 칸 안에 윤곽이 통째로 들어가지 않는 건물의 수와 이름을 적는다. 고치지는 않는다.
- **평가 상자 기록:** 세 평가 상자(B0, B173 주변, R1)가 어느 칸에 들고, 칸 경계(넓히기 전)에 걸리는지 적는다.
- 같은 기록을 넷 판(2 × 2)과 전체 판에도 같은 표로 낸다. 넷 판은 앞 작업의 기록을 옮겨 적으면 된다.

### 3.2 아홉 칸 (항공 LiDAR)

### 3.3 건물 단위 LoD2

- 판 이름 `<장면>ef_LoD2_s0`, `<장면>ef_LoD2_s1`. 장면은 B0, B173 주변, R1이다.
- 명령은 `<장면>ef_ALS_s0·s1`과 같다. 다른 것은 사전 정보뿐이다.

### 3.4 표면 추출과 채점

- 모든 판에서 세 평가 상자의 메시를 기존 메시 규칙으로 만든다. 메시에 쓰는 영상 목록은 건물 단위 장면과 같은 목록이다.
- 채점은 앞 작업과 같은 채점기다(GTJUDGE 단계 1의 칸, 법선 측정선 거리, 덧붙임 2 3.4의 정확성 규칙).
- **경계 띠:** 넷 판과 아홉 판에서, 칸 경계 양쪽 2 m 안에 드는 평가 상자 부분의 완전성과 뜬 면 비율을 따로 센다. 띠에 드는 부분이 없으면 '없음'이라고 적는다.

### 3.5 멈춤 원인 확인

멈춘 판마다 아래 표를 채운다. 앞 작업에서 멈춘 판(2.1의 5번)과 이번에 멈추는 판 모두에 쓴다. 끝까지 돈 판도 추이 기록(1~3행)은 남겨, 멈춘 판과 나란히 볼 수 있게 한다.

| 행 | 볼 것 | 낼 것 |
|---|---|---|
| 1 | 가우시안 수의 추이 | 1,000회마다의 수. 밀도 제어 때마다 늘어난 수 |
| 2 | 길쭉한 가우시안의 비율 추이 | 짧은 축 ÷ 긴 축이 0.01 아래인 비율, 0.1 아래인 비율. 1,000회마다. 저장 파일이 있는 반복에서는 길쭉함의 분포 그림 |
| 3 | 메모리 추이 | 호스트 메모리와 GPU 메모리. 1,000회마다. 멈춘 순간의 값 |
| 4 | 멈춘 단계 | 학습 반복, 밀도 제어, 저장, 평가 렌더, 영상 올리기 가운데 어디서 호스트 메모리가 늘었나 |
| 5 | 자료를 올리는 방식 | 영상과 목표를 한꺼번에 메모리에 올리는가. 영상 수와 해상도, 그것만으로 드는 메모리의 계산값 |
| 6 | 끝난 판과 설정이 다른 곳 | 가장 가까운 끝난 판과 설정 파일, 실행 명령을 줄 단위로 견줘 다른 곳을 모두 적는다 |
| 7 | 장면 크기에서 나오는 값 | 밀도 제어 문턱, 큰 가우시안 정리 문턱의 실제 값. 끝난 판과 나란히 |
| 8 | 가름 | 아래 넷 가운데 무엇인지, 근거가 되는 행 번호와 함께 |

가름의 갈래:
- **가우시안 폭증.** 수가 가파르게 늘고 길쭉한 것의 비율이 함께 오른다.
- **자료 올리기.** 가우시안 수는 얌전한데 영상이나 목표를 올리면서 호스트 메모리가 찬다.
- **설정이나 코드의 잘못.** 끝난 판과 다른 설정, 잘못 걸린 값, 새는 메모리.
- **알 수 없음.** 근거가 모자라면 이렇게 적고, 무엇이 있으면 가를 수 있는지 적는다.

- 가름은 근거가 있는 것만 적는다. 근거 없이 "메모리 부족"으로 끝내지 않는다.

### 5.2 정성 (같은 스크립트로)

- 세 장면마다 건물 단위(씨앗 0, 씨앗 1), 전체, 넷, 아홉의 메시를 같은 세 시점(위, 비스듬히 두 쪽)에서. 참값까지의 법선 측정선 거리로 칠한다.

- 칸 경계가 평가 상자에 걸리면 그 자리의 단면. 걸리지 않으면 경계 띠 한 곳의 메시 그림.
- 칸 나누기 그림: 캠퍼스 위에 넷 판과 아홉 판의 칸 경계(넓히기 전과 뒤), 카메라 위치, 세 평가 상자를 그린다.
- 멈춤 원인 그림: 3.5의 1~3행 추이를 멈춘 판과 끝난 판을 한 그림에 겹쳐 그린다.
- 앞 작업에서 그림 컨테이너가 메모리 한도(32 GiB)로 죽었다. 장면과 판을 하나씩 나눠 그린다. 그래도 죽으면 '없음'과 까닭을 적는다.
