# 학습 단위를 나누는 기준 — 관련 연구 정리 v1

PHD-MAIN-TRAINUNIT-v1, 2026-11-13. 사용자 요청: 학습 단위는 영상 수, 확인 횟수, 가우시안 수 같은 기준과 관련 연구에 근거해 정해야 한다. 이 문서는 큰 장면 GS/NeRF 연구가 단위를 어떤 기준으로 나누는지 정리하고, 우리 측정과 대응시킨다. 판정은 하지 않는다(`scientific_verdict: null`).

## 1. 한 줄 답

관련 연구는 단위를 메모리만으로 정하지 않는다. 다섯 가지를 함께 정한다.

- **크기 상한:** 계산 예산(메모리·시간).
- **크기 하한:** 맥락과 감독 데이터가 충분한지.
- **영상 배정:** 단위마다 그 구역을 충분히 보는 영상을 붙이는 규칙.
- **경계 처리:** 단위 밖 내용과 이음매를 어떻게 다루는지.
- **가우시안 수 다스림:** 2DGS에서는 퇴화 원반 폭증을 막는 장치. 위 넷과는 따로다.

우리 판 다(VastGaussian 2×2)는 상한 쪽에서 이 다섯째 문제로 터졌다. 작은 판(94 m)은 하한·경계 쪽에서 터졌다.

|---|---|---|---|---|
| VastGaussian (CVPR 2024) | 바닥 평면 위 카메라 위치로 칸마다 **영상 수가 비슷하게** m×n. 실험은 칸 8개, 칸당 60,000회, VRAM 10.4–11.9 GB | 경계 **20 %** 넓혀 위치로 고른 뒤, 칸 상자(하늘 포함)를 투영한 넓이가 영상의 **25 %** 넘는 영상을 더함 | 상자 투영(airspace-aware)으로 공중 floater 억제. 합칠 때 원래 칸 밖 가우시안 삭제 | 다루지 않음(3DGS) |
| CityGaussian (ECCV 2024) | 먼저 전체를 거칠게 학습한 **전역 가우시안**을 수축 공간에서 나눠 **블록마다 일감이 고르게**. 블록이 많아지면 블록당 데이터가 줄어 나빠지고 약 3×3에서 가장 좋았음 | 블록 안 카메라 + 그 블록을 빼면 렌더 SSIM이 ε(0.05) 넘게 바뀌는 카메라 | "블록 경계는 깊이 감독이 없어 가장자리에 floater가 생긴다" → 전역 가우시안을 블록 학습의 시작점으로 씀 | 다루지 않음 |
| CityGaussianV2 (ICLR 2025) | CityGaussian 블록 나누기를 그대로 씀(예: 3×3, 4×2) | 같음 | 같음 | **2DGS 병렬 블록 학습에서 폭증 → OOM**: 멀리서 보면 점처럼 작아지는 길쭉한 원반이 큰 기울기를 쌓음. 길쭉함 η = 짧은 축/긴 축이 문턱 아래인 원반은 **복제·쪼개기에서 뺌**(문턱 값은 본문에 없음) |
| Hierarchical 3DGS (SIGGRAPH 2024) | 청크 **50×50 m(걸어서 찍음)~100×100 m(차량)**, "건물·차·기념물 같은 흔한 대상의 맥락을 담을 만큼". 청크당 2–8 M 가우시안, 학습 최대 8–10 GB(V100) | 청크 안 카메라 + 2배 범위 안이면서 청크 안 SfM 점을 50개 넘게 보는 카메라 | 전체 거친 모델(scaffold)과 하늘 상자로 **청크 밖을 채우고**, 밖은 불투명도·색만 학습. 합칠 때 다른 청크에 더 가까운 바깥 가우시안 삭제 | 성긴 촬영에 맞춰 밀도 제어를 고침(평균 대신 최대 기울기) |

## 3. 우리 측정과의 대응

| 우리 관찰 | 대응하는 연구 기준 |
|---|---|
| **판 다 칸 0·2·3이 터짐:** VastGaussian 규칙 그대로(2×2, 20 %, 25 %). 1위 계보가 바늘 꼴 2D 원반(길쭉함 중앙값 0.0003–0.0012, 나머지 0.16–0.27), 단위 안쪽 지붕 | CityGaussianV2가 2DGS 블록 학습에서 보고한 퇴화 원반 폭증과 같은 꼴. VastGaussian은 3DGS 규칙이라 이 장치가 없음. 칸이 그 지붕을 더 먼 영상으로 봄(거리 90 % 지점: 칸 150–211 m, 작은 판 80–89 m)도 이 설명과 맞음. 다만 probe0도 먼 영상이 많아 이것만으로 판이 갈리지는 않음 |
| **작은 판(94 m)은 단위 경계에서 터짐:** 경계에 잘린 지붕, 단위 밖 땅 | CityGaussian(블록 가장자리 floater)·Hierarchical 3DGS(밖은 거친 모델로 채움)가 다루는 경계 문제. 94 m는 Hierarchical의 청크 하한(50 m)보다 크지만 밖을 채우는 장치가 없었음 |
| **기준 B0 판도 상자 밖을 채우는 계보 146만 개(61 %).** 바늘이 아님 | 같은 경계 문제가 기준 판에도 있음. 메모리 안에 들어서 드러나지 않았을 뿐 |
| 영상 수·넓이·영상당 반복 수로는 터짐이 갈리지 않음 | 연구들도 이 양들을 터짐 기준으로 쓰지 않음. 영상 수는 일감 균형(VastGaussian)과 감독 배정에 씀 |
| 가우시안 100만 개당 GPU 메모리 약 2 GB(probe3 9.79 M → 19.3 GB, probe4 7.43 M → 16.4 GB), 칸 0은 9.58 M에서 멈춤 | 크기 상한을 가우시안 수로 잡는 근거(Hierarchical: 청크 2–8 M, 8–10 GB) |

## 4. 근거에 맞춘 설계 순서

1. **가우시안 수 다스림 (CityGaussianV2):** 길쭉함 필터를 넣는다. 확인할 것은 두 가지다.
   - 터진 작은 판(probe3·probe4)과 칸 0 지붕이 터지지 않는지.
   - 기준 B0 판 점수가 씨앗 흔들림 안에 드는지.
2. **단위 밖 처리 (Hierarchical 3DGS·CityGaussian):** 캠퍼스 전체를 거칠게 학습한 모델로 단위 밖을 채운다. 밖은 불투명도·색만 학습한다. 경계 계보와 기준 판의 밖 계보를 줄이려는 것이다.
3. **크기 상한 (가우시안 수):** 1·2를 넣은 뒤 넓이당 가우시안 밀도를 잰다. 단위 하나의 예상 수가 24 GB 안(여유 포함)에 들도록 크기를 정한다.
4. **크기 하한 (맥락):** 건물 전체와 둘레가 들어가야 한다(Hierarchical 50–100 m, CityGaussian "블록이 많으면 데이터 부족"). 경계는 건물을 자르지 않게 한다(PG-SAG).
5. **영상 배정:** VastGaussian(20 %, 25 %) 그대로 또는 Hierarchical(청크 SfM 점 50개 넘게 보는 영상). 판정은 지금과 같다(모든 단위 처리 + 점수 = 기준 + 시간).

## 5. 확인하지 못한 것과 주의

- CityGaussianV2 길쭉함 문턱 값은 본문에 없다(코드에서 확인 필요).
- 건물을 자르지 않는 경계에는 건물 윤곽이 필요하다. LoD2 `GroundSurface` XY는 DEC-P1-019에서 공유 표준 입력으로 건물별 자르기·버퍼에만 허용된다. 단위 경계에 쓰는 것은 사용자 결정 사항이다(ALS·MVS에서 얻는 윤곽이 대안).
- 우리 포크의 화면 크기 지우기는 작동하지 않는다(`densification_postfix`가 `max_radii2D`를 0으로 비움). 관련 연구에서 이를 다룬 1차 출처는 찾지 못했다.
- BlockGaussian·ULSR-GS·Aerial-NeRF·PG-SAG·Momentum-GS는 요약 페이지와 초록 수준만 확인했다.
