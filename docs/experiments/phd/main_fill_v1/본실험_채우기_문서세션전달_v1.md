### 1.1 6.3의 사실 (8.1)

- **기준.** 보조 작업의 `docs/experiments/phd/ch6_support_v1/6장_3절_사실_v1.md`와 문서 세션의 결정(덧붙임 4절)이다.
  - 인용: TUM2TWIN 논문(Wysocki 외, 2026), Zenodo 자료집 판 1.1.0(Anders 외, 2025, doi:10.5281/zenodo.14899378)
  - 표 6.2의 크기는 평가 범위다(B0 71 × 31 m, B173 주변 76 × 54 m, B173만 76 × 32 m, R1 54 × 49 m)
  - R1 학습 영상은 333장이다
  - 정확도 값: 항공 LiDAR는 평탄한 맨땅에서 높이 약 0.10 m, LoD2는 약 1 m
- **대조.** 이 발주의 사실 표는 `tables/facts.md`다(30개). 보조 작업과 다른 점은 넷이다(`tables/facts.md` 4절).
  1. 웹 사실: 보조 작업이 '확인'으로 둔 웹 사실을 이 발주는 '확인 불가 (저장소 문서에 없음)'로 두고, 사본의 내용은 '참고'로 옮겼다.
     - 해당: 자료집 이름과 저자, 논문의 권과 쪽, GeoGS의 권·쪽·DOI, 기기 정확도, LoD2 코드의 뜻과 높이 정확도
     - 번호: F2, F8, F14, F15, F28, F4·F9의 일부
     - 문서 세션이 덧붙임 4절에서 정한 인용과 정확도 값이 이 칸들의 기준이다.
  2. LoD2 지붕을 만든 시기(F13): 보조 작업의 '아직 모름'을 '확인 불가 (GML에 속성 없음)'로 적었다.
  3. 참값 정리 세 줄의 1번에 '+0.75 m' 규칙을 더했다. 설정 `prep_v5.json`의 transient_rule 줄과 맞춘 것이다.
  4. 자료 목록 문서의 'CityGML 2.0'이 파일(1.0)과 다르다는 결론은 보조 작업과 같다.

### 1.4 학습 전 판정의 넓은 범위 검증 (8.4)

- **기준.** 보조 작업 보고서 6절의 주 표, 어긋남 크기별 표, 몰림 표다.
- **이 발주의 값을 쓰는 줄: 영상이 틀린 곳 중 거른 영상 오류.** 발주문 5.3의 정의이고, 일 2의 학습 결과와 같은 영역이다.

  | 갈래 | LoD2 고르는 곳 | LoD2 평가 상자 합 | 항공 LiDAR 고르는 곳 | 항공 LiDAR 평가 상자 합 |
  |---|---|---|---|---|
  | 잘못 놓음 | 30.3 % (873 m²) | 23.5 % (94 m²) | 26.0 % (798 m²) | 92.5 % (30 m²) |
  | 맞게 지킴 | 53.5 % | 71.8 % | 55.4 % | 4.4 % |
  | 코드 3 전제 위배와 겹친 넓이 | 149.5 m² | 11.6 m² | 118.2 m² | 18.7 m² |
  | 겹침을 뺀 잘못 놓음 | 18.2 % (724 m²) | 13.1 % (83 m²) | 15.8 % (680 m²) | 82.7 % (11 m²) |

  - 고르는 곳 = 일곱 탐색 지역에서 평가 상자를 뺀 곳. 항공 LiDAR의 평가 상자는 30 m²뿐이고 R1 반투명 지붕 쪽이다.
  - 겹침을 뺀 줄은 결정 반영 1절의 원칙(판정을 충돌로 바꾼 영상 오류는 '맞는 자료를 판단할 수 없는 곳')에 따른다.
- **거른 영상 오류의 정의는 두 작업에서 다르다.**
  - 보조 작업의 보충 1은 '마스크를 끈 MVS는 τ 넘게 틀리고, 마스크를 켠 쪽은 결측이거나 τ 안'인 패치다. 걸러 낸 뒤 남은 화소가 맞는 패치까지 넣은 넓은 정의다. 고르는 곳의 잘못 놓은 몫은 LoD2 21.0 %, 항공 LiDAR 12.9 %다.
  - 이 발주는 '패치 화소의 과반에서 마스크가 0'인 패치다. 같은 곳의 몫은 30.3 %, 26.0 %다.
  - 6.6.1과 7.1에는 이 발주의 값을 쓰고, 보조 작업의 값은 넓은 정의의 참고로 둔다.
- **'영상이 틀린 곳'의 코드 3 문턱 이내 줄**은 보조 작업의 주 표가 기준이다. 이 발주의 5.4 꼴도 같은 놓은 몫을 낸다: LoD2 10.0 % / 13.0 %, 항공 LiDAR 7.0 % / 17.3 %(고르는 곳 / 평가 상자 합).
- **B173만의 장면 안 값.** 같은 패치로 맞춘 이 발주의 값을 하나로 쓴다.
  - 잘못 지킴: LoD2 9.0 % → 44.1 %, 항공 LiDAR 0.5 % → 89.5 %
  - 보조 작업의 값(9.7 → 40.2 %, 0.5 → 89.6 %)은 참고로 곁에 둔다.
- **판정 지도** (`figures/judge_wide/`, x = 동, y = 북, 실제 방향): 다섯 장 모두 제목이 한 눈에 볼 것 문장이다.
  - B0: 틀린 판정은 대상 건물의 남서쪽 지붕과 건물 가장자리에 모인다. 잘못 놓음 LoD2 5.8 % / 항공 LiDAR 1.8 %.
  - B173 주변: 가운데 유리 톱니 지붕에 모인다. 3.5 % / 2.5 %.
  - R1: 부채꼴 지붕의 가파른 호와 서쪽 반투명 지붕에 모인다. 20.2 % / 27.9 %.
  - B173만: 가운데 유리 톱니 지붕에 모인다. 9.3 % / 4.7 %.
  - 고르는 곳: 일곱 탐색 지역의 여러 건물에 흩어진다. 상위 다섯 동이 47 % / 53 %.

## 2. 재현했다고 밝힐 글감: CDGS

- **변형.** 공식 코드(zqlin0521/cdgs-release db853c1)에 어댑터를 붙였다.
  - 크기 맞추기(시점마다 사전 정보 깊이를 SfM 깊이에 맞추는 축척·이동 맞춤) 하나만 건너뛰는 스위치를 두었다(축척 1, 이동 0).
  - 그 밖의 정렬 대상, 가중 식 0.6 × exp(−150 × 정렬 손실), 솎기는 공식과 같다.
  - 스위치를 끄면 앞 발주의 어댑터 v2와 비트까지 같게 돈다.
  - diff: `provenance/cdgs-release-adapters-v3.diff`(v2 대비), `provenance/cdgs-release-adapters-v3_vs_official.diff`(공식 대비).
  - 까닭: 공식 절차는 앞 발주에서 학습 전에 정한 크기 점검에 걸렸다(사용자 결정 10-15).
- **공식 확인** (B0 LoD2 한 판, 9.6절): 공식과 변형은 다음과 같다.
  - 다르다: 과거 형상 유입률(12.55 대 22.12 %), 전체 완전성(36.51 대 40.72 %)
  - 같다: 관측 오류 유입률(11.02 대 10.98 %), 결측 영역 완전성(8.47 대 8.72 %)
  - 같은지 말하지 못함: 부유 가우시안 수(662 대 922)
  - 두 판 모두 고정 씨앗이 없어 차이에 학습마다의 흔들림이 섞인다. 비교-4는 학습 전에 정한 대로 변형으로 읽었다.
- **실행의 바꿈 (결과를 바꾸지 않는 것).**
  - 일곱 판은 `PipelineParams.debug`를 끄고 돌렸다(사용자 결정 10-18). 소스는 바꾸지 않았다. 계산은 같고 학습은 판마다 329분에서 18~22분으로 줄었다.
  - 평가 메시의 TSDF는 조각으로 나눠 통합했다(사용자 결정 10-18). 설정이 같고, 한 번에 통합한 메시와 삼각형·차례가 같음을 확인했다. 한 번에 하면 B0에서도 96 GB를 넘었다.
- **함께 적을 것 (결과를 본 뒤 더함, 읽기 없음).** CDGS 메시는 발주가 정한 깊이(알파로 나눈 기댓값)로 만들었고, 어느 단위에서나 다음과 같다.
  - 전체 완전성 13~55 %, 정밀도 2.4~11.4 %
  - 유입률 밑에서 결과 면이 참값 쪽에도 틀린 면 쪽에도 없는 몫: 코드 11에서 36.5~87.1 %, 코드 3에서 38.3~85.2 %. 본 방법은 0.2~27.4 %, 1.1~34.1 %다.
- **비교-4의 답** (여섯 단위, 변형(크기 맞추기 생략), 고정 씨앗 없음)
  - 과거 형상 유입률: 넷에서 본 방법이 덜 들였다(확인 3, 가능 1). 둘(B0·R1 항공 LiDAR)에서 더 들였다(가능).
  - 관측 오류 유입률(영역 전체): 여섯 모두 본 방법이 더 들였다(확인).
  - 결측 영역 완전성(0.2 m): 둘에서 본 방법이 더 채웠고, 둘은 같고, 둘(B173 주변·R1 항공 LiDAR)은 CDGS 변형이 더 채웠다(확인).
  - 비가시 영역: 여섯 모두 표본 부족이다.

## 3. 7.6에 쓸 한계 (결정 반영 1절)

- '영상이 틀린 곳'의 한계: LoD2의 문턱 이내 영상 오류는 손실의 허용 구간 안이다. 그래서 설계상 영상만 쓴 결과보다 나을 수 없다(3단계 보고서 8.6).
- 이 발주의 일 2 표는 세 줄로 이 경계를 보인다(`tables/obs_masked_amend1.md`): 거른 영상 오류, 코드 3 문턱 이내, 합친 '영상이 틀린 곳'.
