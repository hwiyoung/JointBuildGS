## 6. 4.1 메모리 부족 기록(r15)

- **r15** = r14 + `jbgs_oom_record.py`(새 파일) + train.py 세 곳(가져오기, 인자 등록, 학습 함수 호출 감싸기)이다.
  - 기본은 꺼짐이다(`--jbgs_oom_record 0`).
  - 켜면 CUDA 메모리 부족이 날 때 traceback의 지역 변수만 읽는다. 그리고 `monitor/oom_record.json`을 쓴 뒤 오류를 다시 던진다. 그러므로 학습은 전처럼 끝난다.
  - 기록하는 것: 반복, 그리던 영상, 가우시안 수, 화면 반지름의 99분위·최대·1만 화소 이상 수, 타일 겹침 합, PyTorch 할당·예약·최대, 장치 사용량(`mem_get_info`, nvidia-smi), 오류 글.
  - 화면 반지름은 렌더가 실패한 반복에는 래스터라이저의 반환값이 없다. 그래서 표면 래스터라이저의 전처리 규칙(`forward.cu`의 근거리 자르기, 변환 행렬, `compute_aabb`, `getRect`)을 파이썬으로 다시 셈한다.
- **확인**: r15(기록 켬, 500회마다 메모리 기록도 켬)와 r14 기본값을 여섯 단위에서 비교했다. 학습 전 계산과 체크포인트 한 반복 모두에서 다른 배열·값이 0개다.
- **반지름 다시 셈의 맞음**: 체크포인트 여섯 곳, 모든 학습 영상에서 래스터라이저가 돌려준 반지름과 비교했다(1억 2천만~1억 9천만 가우시안·영상).
  - 99.65~99.74 %가 정확히 같았고, 0.2~0.25 %가 1화소 달랐다. 영상마다의 99분위는 0.5 % 안에서 같았다.
  - 처음 판은 정수 범위를 넘는 퇴화 가우시안에서 최댓값이 망가졌다. 그래서 래스터라이저처럼 정수 상한에서 멈추게 고쳐 r15를 다시 만들고 같은 확인을 다시 했다(아래 9절).
- **억지 메모리 부족 시험**: GPU 하나를 다른 컨테이너로 거의 채운 뒤 r15 학습을 돌려, 기록이 남고 학습이 전처럼 끝나는지 보았다(아래 9절).

  - 참값 깊이 = 상자 참값 점의 z 버퍼다. 준비 측정의 함수를 그대로 썼다(9×9 새는 점 거르개 0.3 m).

  - 놓친 오류를 \|MVS − 사전 정보\| ÷ τ로 셋으로 나눴다. LoD2의 충돌 문턱은 1τ라 당김 구간 갈래는 모든 조건에서 0이다(발주 5.4가 예상한 대로).

  - 연직 포함 조건의 오류 몫이 같은 수의 저자 조건(18 %)보다 훨씬 크다. 연직 영상과 경사 영상의 짝이 잘 겹치지 않기 때문으로 보인다(가능, 근거 불완전).
  - 이 수는 사진 배치에 좌우되는 데이터의 성질이므로 기록으로 둔다.
