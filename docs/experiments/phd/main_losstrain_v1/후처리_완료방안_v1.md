# 저장된 모델의 남은 후처리 완료 방안

확인: 2026-10-27T21:39:51.445749+09:00

**완료된 학습 모델의 후처리는 재학습 없이 계속할 수 있다.** 현재 장애를 모델 소실이나 학습 중단과 혼동하지 않는다.

|---|---:|
| 30,000회 학습 완료 및 모델 파일 존재 | 19 |
| 메시와 핵심 패치 채점 완료 | 11 |

별도로 학습 중단 4개가 있으며, 대기열의 진행 중 학습은 JSON에 기록했다. 이 기록의 19개 완료 모델과 진행 중 1개가 정상 완료하면, 최종 30,000회 모델로 후처리할 수 있는 범위는 20개다. 중단 4개를 후처리로 완료 판으로 바꾸지 않는다.

## 현재 대기 원인

대기열 상태는 RUNNING, 전체 중지 표시는 []다. 호스트 여유 메모리는 51.30 GiB, 후처리 시작 조건은 56 GiB를 60초 유지하는 것이다. 진행 중인 CPU 8.3 채점이 공유 잠금을 잡고 있으며, 실행기는 CPU 채점과 큰 후처리를 동시에 배정하지 않는다. 따라서 지금 GPU 하나가 쉬는 것은 후처리 오류 증거가 아니다.

성공한 11개 조각 TSDF의 컨테이너 최대 사용량은 21.006~29.141 GiB다. 현재 한도 40 GiB 안에서 완료했다. 모두 항공 LiDAR 결과이므로 아직 처리하지 않은 LoD2까지 메모리 상한을 보장하지 않는다.

## 완료 경로

1. 진행 중인 마지막 학습과 CPU 채점은 유지한다. 학습 종료 후 약 14 GiB의 현재 컨테이너 사용량이 해제되면 후처리 입장 여건이 좋아진다. 실제 여유 메모리는 다시 확인한다.
2. 저장된 30,000회 모델을 같은 영상·카메라·5 cm 복셀·25 cm 절단 거리로 조각별 TSDF 처리한다. 이미 끝난 메시와 표는 다시 계산하지 않는다.
3. 결과를 빨리 읽으려면 남은 LoD2의 메시와 보존 면적·면 없음 넓이를 먼저 채점하고, 가상 시점 및 8.3 추가 지표를 뒤에 배정한다. 이는 처리 순서 제안이며 현재 실행기의 순서를 변경한 것은 아니다.
4. 큰 후처리는 한 번에 하나씩 유지한다. LoD2에서 한도를 넘는 경우에는 실패 단계가 타일 통합인지 최종 합치기인지 먼저 구분한다. 타일 통합은 더 작은 조각, 합치기는 디스크 기반 병합으로 대응할 수 있으나, 구현·동일성 검증을 마친 뒤 적용해야 한다.

## 예상 시간과 조건

완료된 실행에서 가상 시점 단계는 약 1.4~2.6분, 8.3 CPU 채점은 약 9~33분/판이다. 메시 단계는 대기 시간을 뺀 기존 기록상 대략 8~17분/판이다. 현재 실행 중 작업 뒤 핵심 채점을 우선 배정하면 남은 최대 9개 메시·핵심 채점에 약 2~3시간, 추가 지표·검증·전달까지 포함하면 약 6~12시간을 운영 계획 범위로 잡는다. 이는 LoD2가 기존 ALS와 비슷한 실행량이라는 가정이며 완료 약속이나 측정된 LoD2 시간은 아니다. 새 오류·자원 대기가 생기면 그만큼 늘어난다. 현재 순서를 그대로 두면 추가 지표가 핵심 표보다 먼저 실행될 수 있다.

## 바꾼 것

이 조사는 완료 모델·메시·채점 영수증과 실제 최대 메모리를 따로 세었다. 학습·손실·채점 규칙·판·메모리 조건·실행 순서는 바꾸지 않았다. 별도 중단 판 목록에서는 하위 폴더 체크포인트 누락을 수정했다. 그 수정은 남은 정상 모델의 후처리 가능성과 별개다.
