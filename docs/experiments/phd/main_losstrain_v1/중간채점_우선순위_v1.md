# 완료 모델의 채점과 중간 보고를 먼저 확보

2026-10-27 10:40 KST. 전체 학습이 끝나야 채점할 수 있는 구조가 아니다. B173 주변·항공 LiDAR 네 판은 30,000회 모델이 모두 있으며, 그 모델만으로 8.1의 보존·면 없음 넓이와 9.1 날개 단면을 낼 수 있다.

지연 원인은 메시 후처리의 메모리 부족과 배정 순서다. 기존 실행기는 첫 후처리의 메모리 입장 뒤 새 학습을 시작했다. 학습이 실행되면 호스트 여유 메모리가 약 59 GiB로 내려가 다음 후처리의 64 GiB 입장을 늦출 수 있었다. 계산 단계 사이에 다른 새 학습이 다시 배정되는 것도 허용했다.

## 바꾼 것

- 진행 중인 B173 주변·LoD2 다이내믹 참값 학습은 끝까지 둔다.
- 다음 신규 학습의 배정을 잠시 보류한다. 완료된 B173 주변·항공 LiDAR 판 1~4를 각각 메시 후처리 → 추가 후처리 → 채점 순서로 처리한다.
- 채점 가능한 판이 있으면 다음 판의 TSDF보다 그 채점을 먼저 실행한다. 네 판의 채점 뒤 기존 그림 코드로 날개 단면과 중간 보고를 생성한다.
- 중간 보고 생성 기록이 생기면 남은 학습과 후처리의 기존 배정을 자동 재개한다. 판을 빼거나 더하지 않는다.
- 손실, 학습 설정, 채점, 단면 위치·폭, 64 GiB/60초 입장 조건과 48 GiB 후처리 한도는 유지한다. TSDF와 큰 CPU 작업은 직렬 실행한다.
- Docker 검사 8개가 통과했다. 여기에는 채점을 다음 TSDF보다 먼저 실행하고, 그림 생성까지 신규 배정을 보류한 뒤 중간 보고 기록으로 해제하는 검사가 포함된다.

## 예상 확보 시점

새 오류나 긴 메모리 대기가 없고 후처리·채점에 한 판 20~40분이 걸린다는 계획 가정이면, 첫 두 판의 수치는 오늘 11:30~12:30, 네 판의 수치와 날개 단면은 오늘 12:00~14:00 KST를 목표로 한다. 새 방식의 전체 장면 처리 시간은 아직 실측 전이므로 이 범위는 보장이 아니다. 실제 단계별 시간과 완료 기록으로 갱신한다. 이번 우선순위 전환은 나머지 학습의 종료를 늦출 수 있으므로 이전의 전체 학습 15~18시 예상은 고정 약속으로 사용하지 않는다.
