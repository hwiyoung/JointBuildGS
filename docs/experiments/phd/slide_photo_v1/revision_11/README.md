# 5쪽 두 자료 겹침 시안 R11

- 작업: `PHD-SLIDE-PHOTO-v1-R11-SLIDE5-OVERLAY`
- 요청: R10의 분리 배치에서 변화가 읽히지 않아, 같은 위치에 두 자료를 겹쳐 비교한다.
- `scientific_verdict: null`

## 사용할 그림

`figures/slide5_overlay.png`가 3840×2160 최종 겹침 시안이다. `previews/slide5_overlay.png`는 1920×1080 미리보기다. 사진과 비교 형상의 A–B는 기존의 동일한 위치를 나타낸다. 노란 선은 비교 위치이며 표면 마스크가 아니다.

지붕은 원래 ALS 사전 메시의 윤곽을 주황으로, 영상 MVS의 실제 점들을 파랑으로 같은 좌표에 표시했다. 양쪽 면을 비슷한 불투명도로 겹쳐 구분하기 어렵게 만드는 대신, 윤곽과 입체 점 표현으로 나눈다. 낮춘 시점(방위각 −65°, 고도각 15°)에서 높이 간격을 드러낸다. 사전 면의 내부는 8% 색조만 넣었고, 복잡한 내부 메시선은 표시하지 않는다. 이 표시 방법은 겹쳐 비교하기 위한 투시 표현이며 실제 가림을 재현한 렌더가 아니다. 사전 윤곽에는 기존 잘림 범위의 경계도 포함되며, 모두 건물 모서리라는 뜻은 아니다.

벽은 **위에서 본 위치**에 주황 사전 선과 파란 MVS 점, 짙은 드론 LiDAR 참조점을 함께 놓았다. 사전 면 주변에서 영상 점이 앞뒤로 흩어지는 것을 읽도록 한다. 3차원 자료의 정사영이며, 높이 단면 그래프는 아니다. 가로·세로를 같은 미터 축척으로 표시했다. 사진을 찍은 쪽이 위다.

`figures/slide5_prior.png` → `slide5_mvs.png` → `slide5_overlay.png` 순서로 지붕의 사전만·영상만·겹침을 전환할 수 있다. 세 상태는 동일한 시점·범위·축척이며, 아래 벽 비교는 그대로다. 별도 삽입용 `roof_overlay.png`와 `wall_overlay.png`도 포함한다.

## 자료와 표현의 경계

입력 11개는 R9에서 쓰던 원본 그대로다. R10의 고정 표시점과 R9의 고정 범위로 잘린 사전 TIN을 재사용한다. 입력과 캐시, 이전 좌표 감사의 해시를 `input_lock.json`에 고정했다. 비교 범위, 표본 행, 정합, 좌표는 바꾸지 않았다. 현재 사진의 원본과 카메라도 같다. 새 학습·표면 적합·정합은 없다. 원자료 CRS는 EPSG:25832이며 그림은 기존 국소 좌표의 강체 투영이다.

지붕 주황 표시는 원래 TIN 10,190개 삼각형의 투영 윤곽이다. 파랑은 기존 표시 규칙을 통과한 고정 비교 범위의 MVS 42,463점이다. 점 자체의 가림은 실제 깊이 버퍼로 계산한다. 지붕의 현재 드론 LiDAR는 두 자료를 구분하기 쉽도록 본 겹침에서 생략했으며, 이전 R10 비교와 원자료 감사는 보존했다. 이 그림만으로 MVS가 참값이라고 주장하지 않는다.

화살표는 기존 단면의 기하학적 중점에 가장 가까운 기존 0.25 m 구간의 사전·MVS 값을 연결한다. 23번 구간, 단면 거리 5.875 m이며 사전−MVS 높이 차는 원자료에서 7.427694365120665 m다. 최대 차이를 찾아 고른 것이 아니고, 전체 패치의 평균·중앙값도 아니다. 기존 패치 차이 수치와 혼동되지 않게 숫자는 그림에 싣지 않았다. [기존 값 재사용: `main_regionfig_v1/tables/영역예시_보정_숫자.json`, 첫 사례]

벽은 이전 고정 띠의 사전 42점·MVS 670점·참조 43점을 모두 유지했다. 금속처럼 보이는 벽의 외관이 깊이 오류의 확정 원인이라고 주장하지 않는다. 사진과 겹침은 두 입력 사례의 해석을 돕는 자료이며 방법 성능이나 일반화를 입증하지 않는다.

## 처음 보는 사람 점검

별도 에이전트에게 작업 맥락 없이 `qa/without_explanations.png`만 보여 주고 “이 그림이 보여 주는 것을 한 문장으로.”라고 물었다. 제목·결론 문구는 지우고, 자료 이름·시점·A–B는 남겼다.

답: “현재 사진과 대응 위치의 3차원 자료를 비교해, 사전 정보와 영상 MVS 사이의 지붕 높이 차이와 벽면 주변 MVS 점들의 흩어짐을 보여 준다.”

**높이 차이와 벽 점의 산포는 읽혔다.** 이는 제한된 판독 확인이다. 실제 시기 변화의 독립 입증, 어느 자료가 맞는지의 과학적 판정, 사용자 수용을 대신하지 않는다. 이전 R10에서는 두 번 모두 지붕의 세부 형태 차이로 읽힌 한계를 기록했고, 그 그림과 두 답도 패키지에 보존했다.

## 검증·전달

`verification.json`에 원본 좌표, 사전 삼각형의 원래 평면, 고정 범위, 기존 중점값, 동일 미터 축척, 사진 원본 SHA-256과 카메라 재투영, 설명문 제거 시 그림 영역의 동일성, 판독 이미지 해시를 검증한다. 기술적 PASS와 판독 결과를 분리해 기록한다. ZIP은 CRC 및 모든 구성원 SHA-256을 확인한다.

```bash
bash scripts/phd/slide_photo_v1/run_slide5_overlay_11.sh
bash scripts/phd/slide_photo_v1/run_slide5_overlay_11.sh --verify-only
```

기존 `jointbuildgs:dev` 이미지와 원자료가 있는 작업 공간에서 CPU 2개·메모리 4 GiB의 격리된 Docker로 재현한다. GPU와 네트워크는 사용하지 않는다. 원자료는 읽기 전용이며 R11 경로만 쓴다. 이전 R9는 수정하지 않았다. R10은 이번 진행 중 만든 별도 대안과 판독 기록으로 함께 보존한다.

외부 `revision_11/PHD-SLIDE-PHOTO-v1_R11_slide5_overlay.zip`에 그림·R10/R11 문서·설정·스크립트·표시 좌표를 묶었다. 원자료 전체나 Docker 이미지를 포함한 독립 실행 패키지는 아니다. `handover.json`에 경로·크기·해시·검증 결과를 기록했다.
