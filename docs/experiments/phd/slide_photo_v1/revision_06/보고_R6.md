## 1. 기존 지붕을 교체한 이유

기존 B0 면 42의 `DJI_20241217084258_0013_D`는 평가 20화소, 결측 20화소, 참조가 있어 칠할 수 있는 화소 4개였다. 그 20화소에 대한 100%는 맞지만 넓은 지붕의 복원 어려움을 설명할 근거로 부족하다. ‘그 비율이 맞다’와 ‘설명 자료로 적합하다’를 구별하지 못했다. 기존 첫 지붕을 대표 그림으로 쓰는 판단을 철회한다.

사용자의 사례 적합성 지적을 반영해 다음 조건을 사진 확인 전에 고정했다. 기존 세 지역의 학습 시점과 입력 자료만 사용했다.

- 평지붕 법선의 연직 차이 10° 이내, 카메라 기울기 20° 이내.
- 투영 평가 1,000화소 이상, 결측률 50% 이상.
- 면의 고유 평가 패치 중 투영된 패치 비율 50% 이상.
- 연결된 결측 성분 250화소 이상.
- 통과 사례를 결측 화소 수 내림차순, 평가 화소 수 내림차순, 지역·면·시점 순으로 정렬.

참조값이나 학습 결과를 선정에 사용하지 않았다. 334개 면–시점 조합 중 4개가 통과했고, R1 면 23의 `DJI_20241217090901_0033_D`가 선택됐다. 전체 후보와 규칙은 `roof_representativeness_audit.json`에 있다. 이 재선정은 설명용 사례 선정이며 성능·모집단 추론용 표본이 아니다.

결측 39,904개는 원래 깊이값 자체가 유효하지 않은 화소다. 이 사례에서 신뢰도 마스크만으로 추가 제외된 화소는 0개다. 참조는 기존 24개 공개 입력 타일 전체의 카메라별 최근접 Z 버퍼를 재사용했다. 참조가 없는 곳을 이웃 화소로 채우지 않았으며, 참조가 없는 결측 11화소도 분홍으로 칠하지 않았다.

사진에는 지붕 무늬가 보인다. 따라서 제목은 **‘지붕의 깊이 결측’**이다. ‘무늬가 없어서 실패했다’고 해석하지 않는다. 원본 사진에 투영되는 패치는 약 74%이고 면 전체가 들어오지는 않는다. 59%는 **그 시점에서 평가한 지붕 부분**의 비율이며 건물 전체의 결측률이 아니다. 사진 범위는 보이는 입력 지붕 패치로 정했다. 결측·오차 색을 보고 범위를 고르지 않았다.

3쪽의 노란 테두리는 아래 확대 그림의 정확한 범위다. 물체 경계나 결측 마스크가 아니다. 분홍은 깊이값이 없고 참조는 있는 위치, 빨강은 깊이값이 있지만 참조와의 차이가 τ를 넘는 위치다. 무색에는 미평가·참조 없음도 포함되므로 정상이라는 뜻은 아니다.

## 2. 금속 면과 보존은 같은 사례다

두 사진의 원본 JPEG 이름과 SHA-256이 같다. 이 면을 ‘금속이어서 깊이를 측정하지 못하는 곳’이라고 설명하면 부정확하다. 3쪽 사진의 투영 영역에서는 약 **3.3462%가 결측**, **80.0670%가 깊이값은 있으나 참조와 불일치**한다. 핵심은 값의 부재보다 값의 부정확성이다.

보존 그래프는 존재하는 MVS 점과 사전 정보가 참조에서 얼마나 벗어나는지 비교한다. 같은 선택 덩어리 전체의 법선 방향 절댓값 중앙값이 사전 정보 **11.641 cm**, MVS **34.339 cm**, 허용 차이 **20 cm**다. 그래프 숫자는 12, 34로 반올림하고 막대 길이는 원래 값을 유지했다. 사진의 화소별 불일치율과 점군의 거리 중앙값은 계산 단위가 다르며 같은 지표가 아니다.

3쪽 제목은 **‘금속 면의 깊이 오류’**, 6쪽 설명은 **‘깊이값이 있어도 틀리면 / 맞는 사전 정보를 지킨다’**로 바꿨다. 3쪽은 문제를, 6쪽은 그 문제에 대응하는 연구 목적을 같은 장소로 연결한다. 금속처럼 보이는 외관은 원인 입증이 아니다.

## 3. 보정 사진의 다각형 제거

이전 노란 다각형은 보정 패치 중심을 둘러싼 볼록 껍질이었다. 건물 외곽도 지붕 경계도 아니어서 실제 사진에서는 어색하고 잘못된 경계로 읽힐 수 있었다.

R6에서는 다각형과 면 칠을 없앴다. 기존 B173 단면의 240개 3D 좌표를 동일한 원본 카메라에 투영한 **A–A′**만 표시했다. 아래 그래프 제목에도 A–A′를 적었다. 가려지거나 참조를 확인할 수 없는 짧은 선 구간은 끊어서 표시한다. 선은 아래 그래프의 위치이며 건물 경계가 아니다. 단면 좌표·띠 폭·0.25 m 높이 자료·그래프 픽셀은 그대로다.

6쪽의 나머지 사진 설명은 얇은 선과 가벼운 글자로 정리했다. 네 비교 그래프는 R4와 같은 픽셀이다. 4쪽과 11쪽 PNG도 R4와 같은 바이트다. 11쪽은 참값과 제안 방법이 강조된 판을 유지했다.

## 4. 해석 제한

- 보존·보정·다듬기·상속 그림은 입력 근거와 연구 목적을 연결한다. 네 역할의 성공 결과를 새로 검증한 그림이 아니다.
- 상속의 가림 면은 같은 건물의 지붕이다. 이웃 건물이라고 쓰지 않으며, 가려진 벽의 현재 상태나 성공적인 상속을 확인했다고 하지 않는다.
- 다듬기는 B0 면 7의 기존 단면이며 높이를 확대했다. 면 전체 LoD2−참조 중앙값은 −14.61 cm다.
- 참조는 기존 좌표계에 정합된 UAS LiDAR다. 소스 간 일치를 독립적인 실제 표면 검증으로 바꾸지 않는다.
- 11쪽 B173에서는 결합도 참조에 가깝다. 두 사례 모두 결합이 실패했다고 일반화하지 않는다. 제안 방법의 τ 안 비율 85.283%, 100.000%만으로 추가 오류 면이 없다고 할 수 없다.

## 5. 처음 보는 사람 점검

각 변경 그림을 맥락 없는 별도 에이전트에게 하나씩 제시했다. 원문 질문은 “이 그림이 보여 주는 것을 한 문장으로”였다. 답은 목적 이해 점검이며 사용자 수용이나 과학적 검증이 아니다. R4 점검에서 목적이 읽혔어도 사용자는 사례·표시에 문제가 있음을 지적했다.

첫 판독 3쪽: “이 그림은 지붕·그늘진 벽·금속 면에서 영상 기반 깊이값이 누락되거나 참값과 불일치하는 양상이 서로 다름을 확대 영상과 비율로 보여 준다.”

## 6. 재현과 전달 검증

기존 입력 자료와 외부 아티팩트가 있는 저장소에서 실행한다. 원본 사진과 큰 수치 배열은 전달 ZIP에 넣지 않는다. R2–R4 재현 의존성은 기존 R4 보고서와 스크립트에 있다.

```bash
bash scripts/phd/slide_photo_v1/run_cpu.sh r6-scan representative_audit_06.py
bash scripts/phd/slide_photo_v1/run_cpu.sh r6-photo representative_audit_06.py photo
bash scripts/phd/slide_photo_v1/run_cpu.sh r6-a presentation_revision_06.py a
bash scripts/phd/slide_photo_v1/run_cpu.sh r6-e presentation_revision_06.py e
bash scripts/phd/slide_photo_v1/run_cpu.sh r6-retain presentation_revision_06.py retain
bash scripts/phd/slide_photo_v1/run_cpu.sh r6-verify verify_package_revision_06.py "$(git rev-parse HEAD)"
```

`verification.json`은 입력 해시, 선정 규칙, 실제 화소 수 재계산, 단면 투영, 기존 그래프 픽셀, 원본 보존, 배치 크기와 글자 크기를 확인한다. `package_receipt.json`은 ZIP의 SHA-256, CRC, 모든 구성 파일의 SHA-256이다. 실패와 수정은 `issues.md`에 기록했다. 측정·생성 시각과 도구 버전은 JSON과 외부 작업 로그에 보존한다.

R6 선정 규칙 생성은 2026-10-27 11:05:02 KST, 첫 전달 검증 완료는 11:21:30 KST로 약 16분 28초다. 이후 최종 배치 크기의 3쪽·6쪽을 직접 열어 글자 잘림과 단면선 위치를 확인하고 이 기록을 추가했다. 기술 검증 90개 항목은 통과했으며, 독립 판독과 별개로 사용자 수용 판정을 대신하지 않는다.
