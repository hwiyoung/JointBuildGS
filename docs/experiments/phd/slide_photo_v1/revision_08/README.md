- 작업: `PHD-SLIDE-PHOTO-v1-R8-SLIDE5-DRAFT`
- 사용자 요청: 5쪽을 기존 사진과 실제 단면의 prior/MVS 짝 비교로 제작.
- 상태: 시안 제작 및 수치·배치 자체 점검 완료. 맥락 없는 별도 에이전트 판독은 도구 제한으로 미실행.
- `scientific_verdict: null`

`figures/slide5_prior_image_pairs.png`는 3840×2160 원본이고, `previews/slide5_prior_image_pairs.png`는 1920×1080 배치 확인용이다. 16:9 슬라이드 한 장으로 사용할 수 있다. 앞선 그림과 패키지는 변경하지 않았다.

## 구성과 출처

사진을 왼쪽, 사전 정보와 현재 영상 MVS를 가운데·오른쪽에 배치했다. 각 행의 두 그래프는 같은 참조점과 축 범위를 사용한다. 사진의 노란 A–A′는 실제 단면 띠의 중심선이다. 영역 마스킹이나 건물 외곽이 아니다. 사진의 관측 가림 구간은 기존 점선 표시를 유지했다.

1. **바뀐 지붕:** `main_regionfig_v1/tables/영역예시_보정_숫자.json`의 기존 예시 a, B173 단면 전체 48구간. 사전 정보는 2022 항공 LiDAR다. 기존 `reference_zero_model_m`를 세 자료에 똑같이 적용한 상대 높이를 표시한다. R6 사진·카메라·회전·자르기와 측정선은 그대로다.
2. **깊이가 어긋난 벽:** R7의 `candidate_0001`, 건물 `DEBY_LOD2_4906968` 단면 전체 12구간. 사전 정보는 LoD2다. 기존 면 법선 좌표를 cm로 바꾸고 가로 거리의 시작점을 0으로 옮겼다. 참조·prior·MVS의 구간 대표값은 재선정하거나 평활화하지 않았다. R7 사진과 측정선을 그대로 썼다.

같은 행 안에서는 축척이 같지만 두 행의 단위와 축척은 다르다. 벽면 그래프는 위아래 높이가 아닌 면 수직 방향의 앞뒤 위치다. 회색 띠는 기존 참조 구간 중앙값 ±20 cm 허용 범위이며 통계적 신뢰구간이 아니다. 상대 좌표의 원점은 원자료 기록에 보존했다. 원자료 CRS는 EPSG:25832이며 그림은 기존 국소 단면 좌표를 사용한다.

원자료 해시는 설정 파일에 고정했고, 렌더링 전에 `input_lock.json`을 기록했다. 설정: `configs/phd/slide_photo_v1/slide5_draft_revision_08.json`. 실행은 CPU 2개·메모리 4 GiB 제한의 별도 Docker 컨테이너에서 수행했다. 원자료와 기존 산출물은 읽기 전용 마운트다. 새 학습, GPU 실행, 결과 재선정, holdout 접근은 없다.

## 검증과 해석 범위

`verification.json`에는 원자료 해시, 기존 높이 기준점 재현, R6 단면값 일치, 사진 측정선의 카메라 재투영, 두 패널의 동일 축, 모든 구간과 허용 띠가 축 범위에 포함됨, 텍스트가 캔버스 안에 있음 등 11개 검증 결과를 기록했다. 최종 1920×1080 미리보기를 직접 열어 한글·표식·단면과 설명의 배치를 확인했다. prior 점선/MVS 실선과 열 제목으로 색 이외에도 자료를 구분한다.

선·점은 기존 구간 대표값이며 원시점 전체나 연속 메시가 아니다. 벽면 오른쪽 일부 구간은 MVS도 참조에 가까운 그대로 표시한다. 지붕에서도 MVS의 작은 차이는 그대로 남긴다. 원자료의 값이나 형상을 의도에 맞게 움직이지 않았다. 드론 LiDAR와의 일치는 참조와의 일치이며 독립적인 참값 검증으로 확장하지 않는다. 금속으로 보이는 외관이 오류의 원인임을 확정하지 않는다. 두 예시를 전체 건물의 성능으로 일반화하지 않는다.

초견 점검에 요청한 질문은 “이 그림이 보여 주는 것을 한 문장으로”였다. `fork_turns=none`인 새 에이전트 생성이 `agent thread limit reached`로 실패하여 답은 얻지 못했다. 자체 시각 확인을 별도 초견 판독으로 기록하지 않았다. 이 시안의 사용자 검토를 대체하는 통과 판정은 하지 않는다.
