# 5쪽 3차원 겹침 시안 R9

- 작업: `PHD-SLIDE-PHOTO-v1-R9-SLIDE5-3D`
- 사용자 요청: 실사 위치 사진과 사전 정보·영상의 3차원 겹침 비교로 5쪽 시안을 제작.
- 상태: 시안 제작, 원자료 좌표 재현, 정지 그림·GIF 검사, 별도 초견 판독 완료.
- `scientific_verdict: null`

GIF에서는 참조점과 카메라를 고정한 채 자료를 켜고 끈다. 세 PNG를 연속 슬라이드로 놓으면 발표자가 직접 순서를 넘길 수 있다. 사진의 노란 A–A′는 기존 단면 중심선이며 영역 마스크나 건물 외곽선이 아니다. 아래 3차원 그림은 그 선 주변의 기존 고정 범위다. 사진 자체에 3차원 자료를 투영해 겹친 영상은 이번 시안에 포함하지 않는다.

## 자료와 표현

| 사례 | 사전 정보 | 영상·참조 | 고정 범위 |
|---|---|---|---|
| B173 바뀐 지붕 | 기존 항공 LiDAR TIN과 기존 정합 이동량 | 현재 MVS 원시점 / 드론 LiDAR 참조점 | 기존 `figS_c_change.json`의 XYZ 창 |
| `candidate_0001` 벽 | R7 LoD2 평면 표본의 볼록 외곽 안 면 | R7의 MVS 원시점 / 드론 LiDAR 참조점 | 기존 6 m × 1.2 m 단면 띠의 모든 표본 |

설정과 입력 11개를 첫 렌더링 전에 `input_lock.json`으로 고정했다. 벽의 사전 정보 42점, 참조 43점, MVS 670점을 모두 유지했다. 지붕은 기존 범위 안 MVS 430,519점과 참조 289,669점에서 같은 0.12 m 복셀 규칙으로 각각 74,710점과 42,153점을 표시했다. 각 복셀의 첫 원래 점을 사용하며 평균점이나 새 면을 추정하지 않는다. 이는 표시 간소화이며 통계 표본이 아니다. 지붕 사전 메시의 10,190개 표시 삼각형은 기존 TIN을 고정 범위로 잘라 만든 것이다. 실제 TIN의 가파른 면과 불규칙한 경계도 유지했다.

좌표는 모든 자료에 같은 회전·이동을 적용한 국소 좌표다. 세 자료 사이의 상대 이동이나 깊이 과장은 없다. 기존 정합 이동량은 그대로 적용했고, 새 정합을 수행하지 않았다. 벽은 원자료의 수직 방향이 화면의 위로 향하도록 표시 좌표계만 회전했다. 원자료 CRS는 EPSG:25832이며, 새 중력 추정은 하지 않는다. 최종 카메라는 지붕 방위각 −58°·고도각 24°, 벽 −42°·22°다. 설정에 기록된 최초 시점에서 벽의 표시 시점만 조정했다.

주황은 사전 면, 파랑은 MVS 점, 짙은 회색은 드론 LiDAR 참조점이다. 면은 반투명이며 참조점은 겹침을 읽을 수 있도록 표시한다. 실제 카메라의 불투명 가림을 재현한 렌더가 아니다. 바닥의 옅은 격자는 방향을 읽는 보조선이며 측정된 지면이 아니다. 두 사례는 각각 5 m / 1 m 눈금으로 축척을 표시한다. 슬라이드 본문 글자는 24 px 이상이고 3차원 눈금 글자는 약 25 px다.

## 확인 결과와 해석 범위

`verification.json`에 원자료 해시, 고정 좌표계·투영, 사진 측정선 재투영, 글자 배치 등 13개 확인 결과를 기록했다. `source_replay.json`에서는 표시점 좌표를 원자료로 역변환하여 모든 표시점의 실제 출처를 재확인하고, 지붕 복셀 선택과 벽 원시점 목록을 재현했다. 원래 삼각형 평면, 단계별 동일 카메라, PNG 크기, GIF 프레임 수·시간·화질 차이와 파일 해시도 검사했다. 모든 확인은 CPU 2개·메모리 4 GiB 제한의 별도 Docker 컨테이너에서 수행했다.

이 그림은 두 기존 사례의 자료 간 공간 관계를 설명한다. 드론 LiDAR와의 일치를 독립적인 참값 검증이나 전체 성능으로 확대하지 않는다. 벽의 금속처럼 보이는 외관을 MVS 오류의 확정 원인으로 주장하지 않는다. 지붕의 작은 차이와 벽의 참조에 가까운 MVS 점도 그대로 남아 있다. 새 학습·방법 결과·holdout 열람은 없다. R8과 앞선 그림은 변경하지 않았다.

## 처음 보는 사람 점검

두 번 모두 `fork_turns=none`인 별도 에이전트에게 그림 파일 하나만 주고 “이 그림이 보여 주는 것을 한 문장으로” 물었다. 입력 경로, 최종 이미지 해시와 판독문은 `qa/blind_reviews.json`에 보존했다.

첫 표시 시안의 답:

> 바뀐 지붕에서는 옛 사전 정보가 영상·드론 LiDAR보다 위에 남고, 벽에서는 사전 면이 참조 가까이에 있는 반면 영상 MVS 점들이 앞뒤로 흩어지는 모습을 3차원으로 비교한 그림이다.

그 후 벽의 위아래 방향, 사선 시점, 불필요한 내부 삼각형 선과 단계별 설명만 다듬었다. 자리와 값은 바꾸지 않았다. 첫 시안의 이미지 해시는 별도로 보존하지 않았으므로 첫 판독을 최종 파일의 검증으로 사용하지 않는다.

최종 시안의 답:

> 이 그림은 바뀐 지붕에서는 과거 항공 LiDAR가 영상 MVS·드론 LiDAR 참조보다 위에 남고, 벽에서는 LoD2 사전 면이 참조 가까이에 있는 반면 영상 MVS 점들이 앞뒤로 흩어지는 차이를 3차원으로 보여 준다.

두 판독 모두 의도한 두 자료의 차이를 읽었다. 이는 그림의 전달력 점검이며 과학적 판정을 대신하지 않는다.

## 재현과 전달

```bash
bash scripts/phd/slide_photo_v1/run_slide5_3d_09.sh --wall-az -42 --wall-el 22
bash scripts/phd/slide_photo_v1/run_slide5_3d_09.sh --verify-only
```

기존 외부 입력과 `jointbuildgs:dev` 이미지가 있는 저장소에서 실행한다. Docker 이미지 ID, 실행 기준 커밋, 스크립트 해시, 라이브러리 버전은 이 디렉터리에 기록했다. 읽기 전용 원자료와 기존 산출물에 쓰지 않으며 새 R9 디렉터리에만 출력한다. 표시 좌표 NPZ, 구성 요소 PNG와 실행 로그는 외부 payload `slide_photo_v1/PHD-SLIDE-PHOTO-v1/revision_09/`에 있다.

같은 외부 디렉터리의 `PHD-SLIDE-PHOTO-v1_part_R9_slide5_3d.zip`에 그림, 보고, 설정, 재현 스크립트와 표시 좌표를 묶었다. 원자료 전체와 실행 환경을 포함하는 독립 실행 패키지는 아니다. `handover.json`은 ZIP 경로·해시와 구성원별 해시·CRC 확인을 기록한다.
