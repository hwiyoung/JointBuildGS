# SRDM P1/P2/P3 실제 적용 범위

2026-09-08 · `PHD-SRDM-P1P2P3-v1` · `scientific_verdict: null`

사용자의 최신 지시 “일단 P1/P2/P3에 대해 SRDM 적용해보고 정량/정성 분석해보자”에 따라 이 세션의 범위를 SRDM 구현·실행·분석까지 확장한다. 이전 설계 문서의 무실행/범위 확인 대기는 당시 상태로 보존한다. 별도 세션의 GeoGS 실행·파일·서비스는 변경하지 않는다.

첫 적용은 SRDM 두 단계 판단·복원의 논문 기반 재구현이다. 공식 저자 실행 코드는 확보하지 못했다. 원논문에서 별도 연구로 인용한 자세 정합은 기존 공통 카메라/ALS 정합으로 대체한다. 원형에서 미명시된 설정과 참조된 특징/전처리의 재구현 선택을 코드 대응표에 남긴다. 기존 방법의 수치 재현 또는 원형 전체의 성능 인증으로 표현하지 않는다.

세 지역마다 공통 학습측 영상에서 카메라 기하만으로 한 쌍을 선택한다. ROI의 고정 격자 공통 투영 피복, 광선 교차각, 투영 면적과 명시된 동률 규칙을 사용하며 RGB 잔차·ALS 일치도·UAS 점수를 사용하지 않는다. 한 스테레오 쌍에서 관측할 수 있는 범위의 개발 진단이며 모든 학습뷰의 다중시점 복원과 동일 조건이라고 부르지 않는다. 영상만/불일치 제거 끔/두 단계 SRDM 세 조건은 같은 쌍·원해상도·정류·구현을 사용한다.

전처리와 알고리즘을 먼저 검사하고, P1/P2/P3 중간 판단과 세 조건의 결과를 봉인한 뒤 평가 참조를 연다. 원형 판정에서 제외된 점과 관측/계산이 불가능한 점을 구분한다. 독립 참조와의 거리 분포는 판단의 오류를 해석하는 진단이며 최근접 거리만으로 시간차·가림·소스 권위를 확정하지 않는다.

실행 자원은 기존 Docker image, CPU 4개, RAM 12GiB, GPU 미사용으로 시작한다. 실제 자원 부족은 새 attempt와 실패 영수증으로 보존하며 기존 작업을 중단하거나 삭제하지 않는다. 모든 입력은 읽기 전용, 새 출력은 SRDM task 경로에만 기록한다. 모델 코드·설정은 실행마다 별도 source snapshot과 SHA로 연결한다.

P1 첫 attempt의 임시 memmap I/O 병목 이후 저장 방식만 변경했다. P1/P2는 RAM, P3는 사진 비용만 파일에 둔 hybrid로 실행한다. P3 RAM 한도는16GiB, 시작 시 host available 최소32GiB이며 P1/P2는12/24GiB다. 계산식·해상도·알고리즘 파라미터는 유지한다. 중단 attempt와 부분 출력은 보존하고, 저장 방식 동등성 합성검사와 전체32개 Docker 검사를 통과한 버전으로 재개한다.

P3 실행 중16GiB 캐시 회수 병목을 확인하여05:33:35UTC에 해당 컨테이너만20GiB로 늘렸다. 당시 host available은43.05GiB였고 OOM은 없었다. 원16GiB launch와 추가 자원 영수증을 함께 보존한다. 이후 재실행 설정은20GiB/시작 여유40GiB로 기록하며, 실제 이번 실행은16→20GiB였음을 구분한다.

최종 산출물은 실제 판단 mask/원점 대응, 세 조건의 시차/깊이/점군, 정량표·평가 원자료, 원영상·동일시점 점군·고정 단면 그림 및 개선·유지·악화·판단 불가 분석이다. GS 학습이나 GS 뒤 재판단은 이번 SRDM 실행에 포함하지 않는다. GS 뒤 SRDM 판단을 적용할 때는 입력 추정의 변경과 자기 강화 가능성을 별도 검증한다.
