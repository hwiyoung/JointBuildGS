# 잔차에서 실제 Gaussian 갱신으로 연결하는 선행연구

2026-09-08 · 문헌 확인 및 설계 후보 · `scientific_verdict: null`

기존 `GS_INTEGRATED_SOURCE_UPDATE_CANDIDATE_ko_v1.md`의 감독 완화안에 대한
사용자 질문을 다룬다. 기존 기록·방법 채택 상태·SRDM 결과를 변경하지 않으며,
이번 작업은 원문·공개 코드의 읽기와 문서 정리다. 새 실험·학습은 실행하지 않았다.

## 표현 정정

- **지속적인 복합 잔차**는 특정 논문의 정식 방법명이 아니라 앞선 설명의 표현이다.
  기하·외관 최적화가 진행된 뒤에도 같은 표면에서 여러 유효 뷰에 걸쳐 불일치가
  반복된다는 뜻이다. RGB·영상 유래 depth·normal을 함께 살피되 세 잔차가 모두
  커야 한다는 규칙은 아니다. 높이만 틀린 평면은 normal 잔차가 작을 수 있다.
  같은 depth에서 만든 normal과 depth는 독립 증거가 아니다. 반복은 새 관측을
  만들지 않으며, 같은 오차를 여러 번 본 것 자체가 별도 증거가 되지 않는다.
- **영상 기하가 GS를 수정하도록 허용**은 우선 prior 감독·보호를 완화해 기존
  Gaussian의 이동을 허용한다는 뜻이었다. 이것만으로 소스 전환을 구현했다고
  할 수 없다. ALS 지지 표면을 MVS 지지 표면으로 실제 전환하려면 충분한 재배치,
  또는 MVS에서 Gaussian 추가와 기존 표면 기여 축소/비활성화가 필요하다.
  새 Gaussian 객체 생성이 모든 전환의 필수 조건은 아니다. 초기화 출처의
  이력과 현재 어느 근거가 기하를 지지하는지도 구분한다.

## 원문에서 확인한 실제 갱신

### RTG-SLAM — SIGGRAPH 2024

[원문 §3.2](https://arxiv.org/html/2404.19706#S3.SS2),
[공식 구현](https://github.com/MisEty/RTG-SLAM)

RGB-D 입력과 현재 GS 렌더를 비교한다. 미복원 영역 또는 큰 depth 오차에는 입력
깊이에서 불투명 Gaussian을 추가한다. depth는 맞고 RGB만 틀리면 기존 Gaussian이
unstable일 때 계속 최적화하고, stable일 때는 투명 Gaussian으로 외관을 보정한다.
원문은 stable Gaussian의 RGB 또는 depth 오류 횟수가 쌓이면 unstable로 되돌리고,
오래 안정화되지 않는 Gaussian은 삭제한다. 픽셀과 Gaussian을 연결하는 index map을
사용한다. 이는 잔차 종류에 따른 구조/외관 조치와 국소 재활성화의 직접 선례다.

현재 공개 코드 commit `49dada148551961e2dee38040a4f760fa1b0f01d`의
`gaussians_release`는 `stable_pointcloud.remove` 뒤 같은 stable 집합에 `cat`하는
내용이 있어 원문의 stable→unstable 전환과 차이가 있다. 실행으로 효과를 확인한
것은 아니다. 재현 시 이 부분을 먼저 점검해야 한다.
[확인 코드](https://github.com/MisEty/RTG-SLAM/blob/49dada148551961e2dee38040a4f760fa1b0f01d/SLAM/multiprocess/mapper.py#L286)

수정 기하의 기준은 센서 깊이다. 저자는 반사·잘못된 깊이에서 저하를 명시한다.
MVS 깊이를 대입하는 것만으로 P3의 올바른 ALS 보존이 해결되지는 않는다.
[공식 깊이 한계 설명](https://github.com/MisEty/RTG-SLAM#4-evaluate)

### GaussianUpdate — ICCV 2025

[원문 §3.2–3.3](https://arxiv.org/html/2508.08867v1#S3),
[공식 프로젝트](https://zju3dv.github.io/GaussianUpdate/)

기존 GS와 현재 다중 RGB·pose를 사용한다. SAM 인스턴스의 일치로 구조가 유지된
영역을 찾아 외관 모델을 먼저 최적화한다. 이어 외관 모델을 고정하고, 기존 Gaussian
opacity에 곱하는 제거 인자와 COLMAP 기반 신규 Gaussian을 RGB 손실로 최적화한다.
제거 인자가 작은 Gaussian을 공간 군집으로 정리해 활성 장면에서 제외하고 새
Gaussian을 densify한다. 마지막으로 외관 모델과 신규 Gaussian을 함께 정제한다.
기존 중심 전체를 자유롭게 다시 학습하는 방식은 아니다.

제외된 Gaussian은 visibility pool에 보존해 과거 시점 재현에 사용한다. 과거 재현은
초기 오판을 알아내 자동 재채택한다는 보장은 아니다. 별도 소스 선택 GT 학습은
없지만 SAM 사전학습과 장면별 외관 모델 학습은 사용한다. 공식 프로젝트에서
공개 구현 링크는 이번 확인 시 찾지 못했다.

원문 §5는 강한 반사에서 잘못된 기하·외관 갱신의 한계를 명시한다. ALS와 MVS의
상대적 신뢰도, 유보, 현재 관측 부족 영역의 구조 보존은 별도 검증 대상이다.

### GS-LTS — 2025 사전공개 원문

[원문 §IV-C–D](https://arxiv.org/html/2503.17733v1)

현재 RGB와 과거 GS 렌더의 픽셀·특징 차이에서 객체 추가/제거/이동을 판단한다.
여러 영상의 대상 마스크에 Gaussian 중심을 투영해 대상 집단을 정한다. 추가는
현재 깊이에서 생성, 제거는 관련 Gaussian 삭제와 현재 깊이 기반 빈자리 보충,
이동은 삭제 후 추가로 처리하고 미세 조정한다. 영역 판단과 실제 Gaussian 집단
편집을 연결하는 선례다. 로봇이 추가 다중 RGB-D를 수집하는 조건과 실내 객체
설정이므로, 고정 항공 영상·pose만 쓰는 우리 조건이나 지붕 의미 단위 선택의
완성된 해법으로 확대하지 않는다.

### SplaTAM — CVPR 2024: 더 단순한 추가 규칙

[원문](https://openaccess.thecvf.com/content/CVPR2024/papers/Keetha_SplaTAM_Splat_Track__Map_3D_Gaussians_for_Dense_RGB-D_CVPR_2024_paper.pdf),
[공식 추가 코드](https://github.com/spla-tam/SplaTAM/blob/main/scripts/splatam.py#L347-L387)

유효 입력 깊이 중 낮은 silhouette의 미복원 픽셀, 또는 입력 표면이 렌더 표면보다
앞에 있고 깊이 불일치가 큰 픽셀을 역투영해 Gaussian을 추가한다. 이후 RGB·깊이로
지도를 최적화한다. 앞쪽 새 표면 추가에 비대칭적인 규칙이며, 잘못된 앞 표면을
뒤쪽 현재 표면으로 바꾸는 완성된 소스 전환기는 아니다. pruning도 잔차 지정
삭제와 같지 않다. 외부 깊이에서 실제 새 표면을 넣는 간단한 선례로 보존한다.

## 이번 논의에서의 추천과 미결정

AGS-Mesh/SLS의 감독·관측 갱신 선례를 배제하는 것이 아니다. 이번 질문은 그
판단이 실제 Gaussian 구조 변경으로 이어지는지를 묻기 때문에 이 문헌을 추가했다.

**기존 GS를 현재 영상으로 갱신하는 전체 구조의 주 참고는 GaussianUpdate가 가장
직접적이라는 검토 의견**이다. 제거 인자와 영상 기하 추가를 GS 최적화에 연결한다는
이유다. 코드 즉시 적용의 확정은 아니다. RTG-SLAM은 잔차별 조치와 양호한 영역을
유지하면서 문제 Gaussian을 다시 여는 세부 원리의 참고다. 여러 방법을 조합한
구현을 이번에 결정하지 않는다.

우리 후보 흐름은 `prior GS → 현재 관측과 비교 → 기존 Gaussian 기여 조절 및
필요한 현재 기하 추가 → 같은 장면의 GS 계속`으로 설명할 수 있다. MVS를 무조건
기하 정답으로 삼지 않고 원영상·pose의 지지와 가시성을 사용해야 한다. 대체안의
검증 및 채택/복구, 원 ALS·MVS 후보 보존, 오배제 prior의 재채택은 추가 설계다.
이들 논문이 앞서 제안한 변경 전후 비교·되돌리기까지 통째로 검증했다고 말하지 않는다.

고정 영상에서의 반복 판단은 새 관측을 받는 지도 갱신과 구분한다. 최초 판단 고정
대비 반복 판단의 효과, P1/P2의 현재 기하 회복과 P3의 유효 prior 보존을 함께 확인할
필요가 있다. 이번에는 문헌 적합성만 검토했고 효과에 대한 scientific verdict는 null이다.

## 후속 논의: overview 해석과 GeoGS 연결 후보

사용자는 GaussianUpdate가 현재 사용 중인 기하의 적합성을 검사해 다른 소스로
치환하려는 아이디어에 부합하는지, update 부분을 GeoGS에 연결할 수 있는지 질문했다.
**유지·대체를 GS 최적화로 수행하는 원리에는 부합하고 기술적 연결도 가능하다는
설계 판단**이다. 소스별 정확도를 따로 판정하는 완성된 분류기를 제공한다는 뜻은 아니다.

그림의 `Current GT`는 현재 RGB 학습 영상이고, `Replay`는 과거 GS의 합성 영상이다.
후자는 과거 정보를 보존하는 감독이지 기존 기하의 정확성을 확인하는 독립 관측이
아니다. 시간 `T=N→N+1`은 새로운 촬영 시점이며 같은 영상으로 진행하는 최적화
반복을 뜻하지 않는다. Visibility pool은 시점별 활성 상태를 보존한다.

원문의 세 단계는 다음과 같다.

1. 구조가 유지된 것으로 추정한 영역에서 외관 모델을 최적화한다. SAM의 영역
   일치가 이 마스크를 제공한다. 기존 중심을 이동·추가·삭제하는 단계는 아니지만
   외관 모델이 scale과 SH를 출력하므로 기하가 완전히 고정됐다는 표현은 피한다.
2. 외관 모델을 고정하고 기존 Gaussian의 제거 인자와 현재 SfM 기반 신규 Gaussian을
   함께 최적화한다. 이후 제거 인자와 공간 군집으로 기존 활성 영역을 정리한다.
   미리 정한 한 표면의 ALS/MVS 점수 비교 또는 지붕별 이산 선택과는 다르다.
3. 외관 모델과 신규 Gaussian을 함께 정제한다.

[원문 §3.2–3.3](https://arxiv.org/html/2508.08867v1#S3)

GeoGS 연결 후보는 `prior 초기화와 안정화 → 외관 오차 정리 → 기존 기여 인자와
MVS 기반 신규 Gaussian 최적화 → 갱신 상태의 GS 정제`다. 하나의 장면을 이어가며
국소 추가·비활성화를 수행할 수 있고 전체 초기화를 필수로 두지 않는다. 원문의
신규 SfM 초기값을 보유 MVS로 바꾸는 것은 명시할 적용 차이다. 이때 원영상·pose는
관측 기준이며 MVS는 오류를 포함하는 대체 기하 후보다.

GeoGS 고정 커밋 `db40c95c657ec03ff21c83cb99cf39f4e90247a6`은 두 축의 크기를
갖는 평면 surfel 표현이다. opacity 입력에 제거 인자를 연결하고 신규 surfel을
추가할 수 있는 구조지만 GaussianUpdate의 3D 표현 그대로의 이식은 아니다.
기존 추가 경로는 optimizer 상태와 보호 마스크를 확장한다. 신규 인자·소스 이력도
같이 관리해야 한다. 이는 코드 읽기에 따른 가능성 확인이며 구현·실행 검증은 아니다.
[표현·추가 경로](https://github.com/zqlin0521/GeoGS/blob/db40c95c657ec03ff21c83cb99cf39f4e90247a6/scene/gaussian_model.py#L306),
[opacity 입력](https://github.com/zqlin0521/GeoGS/blob/db40c95c657ec03ff21c83cb99cf39f4e90247a6/gaussian_renderer/__init__.py#L62)

통합 시 남는 연결 사항은 다음과 같다.

- 외관 보정을 생략하고 초기 큰 RGB 오차를 구조 제거로 연결하지 않는다. GeoGS의
  선행 정제가 원문의 1단계 역할을 어느 정도 대신하는지는 확인이 필요하다.
- GeoGS 보호는 opacity를 전부 고정하지 않는다. 게이트 적용이 불가능한 것은
  아니며, 최종 삭제 제한·선택적 opacity floor와 갱신 동작을 맞춰야 한다.
- prior 깊이 감독이 대체 MVS 표면을 과거 깊이로 다시 끌지 않도록, 전환 영역의
  감독과 보호 대상을 함께 정한다. 전체 장면의 보호 해제를 필수로 두지 않는다.
- 과거 시점 재생용 4D hash/Replay 전체를 도입할 필요는 아직 정하지 않았다.
  단일 현재 시점의 소스 활용 갱신으로 단순화하면 원형 재현과 구분한다.
- SAM 마스크와 DBSCAN이 지붕 의미 단위 선택을 보장하지는 않는다. P3처럼 영상
  기하가 잘못된 경우의 prior 유지와 오배제 후 복귀는 별도 검증 대상이다.

기존 판단 모듈의 입출력만 바꾸어 꽂는 구조보다, **기존 기여와 신규 기하를 함께
갱신하는 최적화 블록을 GeoGS에 연결하는 후보**로 기록한다. 명시적 소스 선택,
원형 업데이트, 최소 이식안, 반복 재판단은 아직 같은 방법으로 확정하지 않았다.
`scientific_verdict: null`을 유지한다.
