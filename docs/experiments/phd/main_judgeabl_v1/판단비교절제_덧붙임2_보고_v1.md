## 검산, 바꾼 것, 확인 불가

- 점 단위 목표 맞음 = 앞 묶음 `s_all_variants`(판 x 경우 x 면 976칸 가운데 976칸 같음). 경우별 패치 수 + 네 경우 밖 + 동률 + 점 3개 미만 = 참값 있는 패치 수(모든 면 같음, `p_patch_counts` check_sum). 가 + 나 + 다 = 틀린 점 수(모든 칸, `p_gap_split` check_sum).
- 상한 판의 패치 판정 이름 맞음은 100 %가 아님: LoD2 41,512/1,403,917 패치 ({"일치→사전정보 사용": 36807, "영상 깊이 사용→결측": 4600, "영상 깊이 사용→제거": 105}); ALS 5,727/712,651 패치 ({"일치→사전정보 사용": 5659, "영상 깊이 사용→결측": 61, "영상 깊이 사용→제거": 4, "영상 깊이 사용→미판정": 3}). JC 상한 규칙이 일치인데 u_M이 없으면 사전정보 사용으로, 영상 깊이 사용인데 MVS 높이가 없으면 본 방법 판정으로 두기 때문.
- 고침(덧붙임 2 중 발견): 패치별 판정 파일과 본 표의 바뀐 넓이·바뀐 방향에서 '패치 다수결 상한'의 패치 판정이 본 방법 복사본이었음(JC judge/base 의 oracle 칸). JC `patches_<prior>.npz` oracle_region 으로 고쳐 다시 냄. 점 단위 값은 영향 없음(바뀐 칸은 상한 줄의 changed_area_m2 뿐).
- 기존 4(세 실험 지역)는 JUDGEAPPLY 패치에서 패치 단위로 셈(`p_fusion3_patch`, 네 경우의 패치 수 LoD2 122,740 / 28,309 / 4,030 / 3,185; 항공 LiDAR 52,360 / 7,900 / 4,415 / 278).
- 섞인 패치 비율은 `p_mixed`(다수 비율 100 / 80~100 / 50~80 / 50 % 아래, 경우·자리마다).
