# Source별 적합도 값에서 가중치로 연결하는 주설계 v3.6

후속 [v3.7 고정 사례 진단](NORMAL_PHOTOMETRY_RESULT_ko_v3_7.md)은 depth·normal 기반 비용의 계산과 참조 오차의 관계를 검증한다. 9×9 비용이 더 부정확한 source를 지지하는 반례가 남았으므로, 아래 E→가중 함수는 아직 실행 정책으로 확정하지 않는다.

## 1. 사용자 의도와 앞선 설명의 정정

사용자가 일관되게 요청한 것은 source별 적합도 값을 계산하고 그 값에 따라 source별 감독 가중치를 설정하여 공간 가중치 지도를 만드는 것이다. 이를 '승자를 먼저 고르고 그 source만 사용하는 이진 선택 문제'로 좁혀 설명한 것은 부정확했다. v3.5에서 유지한다고 표현한 '점수→판단'은 이번 정정에 따라 '점수→가중치 설정'으로 명확히 한다.

    각 위치 p에서
    Prior depth/normal + 허용된 관측 → E_P(p)
    Image depth/normal + 같은 관측 → E_I(p)
    E_P(p), E_I(p), 관측 지원/결손, 기존 계수 → w_P(p), w_I(p)
    위치별 두 가중치 지도 → 각 source depth 잔차의 계수 → GS 최적화

여기서 image는 한 비교의 DA3 또는 MVS다. Normal 추가 제안은 앞부분의 source별 적합도 값을 더 유용하게 계산할 수 있는지에 관한 것이다. source별 평가를 생략하거나 Prior를 기각한 곳을 영상 depth로 자동 채우는 요청이 아니다.

## 2. 아직 정하지 않은 것

두 값에서 두 가중치로 가는 공통 함수 W를 설계해야 한다. 점수가 비용이면 낮을수록 사진에 맞는다는 방향과, 유효 관측의 지원 정도를 함께 고려한다. 상대 순위만으로 전체 감독을 강하게 만들면 두 source 모두 부적합한 경우를 놓칠 수 있으므로 배분과 총강도는 구분해 검토한다.

W가 연속 함수인지, 구간별 함수인지, 특정 상황에서 0/1을 허용하는지, 총강도를 유지/감쇠하는지와 수치 문턱은 아직 확정하지 않는다. '가중치'라는 사용자 표현을 곧바로 softmax, 합이 1인 정답 확률, 두 source가 항상 양수인 정책으로 단정하지 않는다. 이진 선택도 가능한 특수한 가중 정책이지만 필수 중간 단계나 이미 확정된 주정책으로 두지 않는다.

v3의 IMAGE_SUPPORTED/PRIOR_SUPPORTED 분기에서 전체 계수를 한쪽에 주는 식은 앞서 제안한 후보 정책으로 보존한다. 이번 사용자 정정 이후의 주설계 요구 자체로 취급하지 않으며, 가중 함수 선정은 다시 검토해야 한다. 기존 기계 판독 v3 설계는 실행 가능 플래그 false인 역사적 설계안이며 새 실행의 가중 함수 결박으로 사용하지 않는다.

## 3. 유지할 구분과 검증

- 관측 적합도 값, 관측 지원 상태, 실제 loss 가중치, 최종 기하 정확성은 서로 다른 산출물이다.
- 가중치 지도는 사진 전체에 하나의 계수를 주는 것이 아니라 픽셀 위치에 따라 w_P와 w_I가 달라지는 것을 뜻한다.
- 관측 부족/결손의 처리는 값→가중치 함수에 명시한다. 사용자의 Prior 유지 의도는 보존하되, 이를 Prior 정확성이 입증된 것처럼 표시하지 않는다. 기존 zero-lambda 조건에서 비활성 source를 되살리지 않는다.
- 원 depth에서 계산한 normal은 파생량이며 독립 관측으로 중복 가산하지 않는다. 별도 normal 점수항을 넣는다면 source별로 같은 기준과 지원을 사용한다.
- 지도 검증은 어느 source를 선택했는지만으로 제한하지 않는다. 두 실제 계수, 배분 비율, 총강도, 결손 처리, 연속/구간별 변화와 source별 오차가 어떻게 연결되는지 평가한다.
- 값과 가중 함수는 GT 없이 고정하고, GT는 이후 별도 평가에만 사용한다. 가중치가 가우시안 변위 비율이나 정답 확률이라고 주장하지 않는다.

현재 v3.2 뷰어는 source별 사진 비용을 계산한 8개 위치의 진단이다. 새 W 또는 전체 가중치 지도는 아직 구현·검증되지 않았다. 다음 설계 작업은 normal을 활용한 E 계산과 E→W 변환을 분리해 구체화하는 것이다.
