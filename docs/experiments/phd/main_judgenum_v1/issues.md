# PHD-MAIN-JUDGENUM-v1 — 확인 불가와 수정 기록

- 계산 확인에서 바깥 면 탐색의 시작 범위를 줄이는 코드가 첫 구간을 0.30 m 건너뛰는 오류를 찾았다. 모의 점과 앞 작업 `find_face`의 직접 비교에서 검출했다. 첫 구간의 아래 끝을 기준으로 시작하도록 수정했다. 실제 자료의 원통 셈은 시작하지 않은 상태였다. 수정 뒤 같은 직접 비교를 다시 실행한다. 최초 실패 로그는 작업 페이로드의 `logs/verify_*.log`에 보존한다.
- 설정용 원자료에서 법선 미정의 1,091개, 사전 정보 흔들림 미정의 9,192개를 확인했다. 수를 0으로 대체하거나 상속으로 해석하지 않는다. 원통 또는 검출 한계를 구할 수 없는 행은 확인 불가로 별도 기록한다.
- 첫 설정 잠금에는 단면 선택 규칙을 기록했고, 좌표는 표본 셈 뒤 그 규칙으로 확정한다. 앞 설정과 잠금 파일을 `judgenum_v1.r0.*`에 보존하고 변경 시각·이유를 추가한다. 원통 셈 전에 좌표를 잠근다. 모든 좌표를 최초 표본 셈 전에 잠근 것은 아니다.
- 단면 선택에서 현재 NumPy가 문자열 배열의 `min` 연산을 지원하지 않아 실행이 중단됐다. 문자열의 사전순 비교를 Python 기본 연산으로 고쳤다. 선택 규칙은 같다. 실패 로그를 보존한다.

- 항공 LiDAR 패치 법선은 원자료 TIN 삼각형의 법선이다. 이 법선을 만든 평면 맞춤 둘레 크기와 잔차 표준 편차가 없어 25배 규칙의 통과·미달을 구할 수 없다. 다시 법선을 맞추지 않고 확인 불가로 남긴다.
- 지붕·벽에 함께 걸친 덩어리에서 두 최소 넓이가 서로 다른 처리를 요구하면 처리 뒤 판단과 처음 선택을 확인 불가로 남긴다. 새 문턱을 만들지 않는다.
- 실제 최소 넓이 집계 첫 실행에서 사전의 키에 패치 구분 번호 대신 배열을 넣어 `TypeError`가 발생했다. 구분 번호로 수정하고 건물별 최대 덩어리의 95% 값과 작은 덩어리 처리 검사를 추가했다. 원통 결과는 유지하며, 실패 로그와 앞 코드 잠금 해시를 보존한다.
- 단계 가의 중간 보고·커밋보다 최소 넓이 집계의 시험 실행이 먼저 시작됐다. 순서 오류를 확인해 이 작업의 집계 컨테이너만 중단했다. 사진 조합·threshold2 선택 결과는 아직 없으며, 단계 가 기록과 커밋을 완료한 뒤 집계를 재개한다. 중단 종료 코드 137은 이 운영 중단에서 나온 것으로, 메모리 초과나 학습 중단이 아니다.
- 전체 행의 cm 단위 검출 한계 재계산 검사에서 MVS 어긋남의 cm 내보내기가 float32로 반올림되는 것을 확인했다. 실제 검출 한계 셈은 원래부터 float64였으며, 내보내기도 float64로 바꿨다. 원통·검출 한계·판단 값은 바꾸지 않고 원래 float32 입력도 함께 보존한다. 앞 내보내기 파일은 별도 보존한다.
- 0.5 m 민감도 집계에서 지붕·벽 사진 작업이 같은 문자열의 point_id를 따로 사용한다는 점을 놓쳤다. 두 작업의 묶음이 합쳐지는 연결 오류를 확인했다. 원래 작업 구분을 연결 키에 붙여 기존 각 작업의 묶음을 유지한다. 기본 0.25 m와 다른 민감도에는 영향이 없으며, 앞 0.5 m 결과를 보존하고 다시 계산한다. 확인용 실행 전 검증한다.
- 확인용 실행 앞에 0.5 m 수정 완료 검사를 추가했다. 대기 중이던 첫 실행은 이 검사에서 멈췄으며 확인용을 계산하지 않았다. 수정·검증 완료 뒤 재실행했다.
- 포장 스크립트의 문법 사전 검사에서 닫는 괄호 하나가 남은 오류를 찾았다. ZIP 생성 전에 수정했다. 계산값에는 영향이 없다.
