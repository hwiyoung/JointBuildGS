# 소스 판단 후 2DGS: 백그라운드 비교 실험

`PHD-SOURCE-SELECTED-2DGS-v1` · 2026-09-15 · `scientific_verdict: null`

사용자가 이전 실험의 근거로 소스 판단 영역을 도출하고, 백그라운드 실험과 단계별
결과 생성을 승인했다. P1/P2/P3에 대해 **직접 소스 구성의 효과**와 **그 구성 위에서
2DGS로 최적화한 효과**를 분리한다. 기존 native GeoGS Gaussian ID의 국소 연결을
요구하지 않고, 선택된 원 깊이 표면으로 planar primitive를 새로 초기화한다.

## 입력과 영역

원 입력은 기존 ALS 표면을 보정한 Prior 깊이와 현재 영상 계보의 COLMAP MVS 깊이다.
같은 원영상·pose·camera-Z 단위와 고정 지역 XY를 사용한다. 이전 소스 관측 판정에서
통과한 P2 11개, P3 2개 7×7 패치만 MVS 채택 영역으로 사용한다. P1의 통과 영역은
없으므로 음성 대조로 유지한다. 이는 전체 변화 영역을 검출한 결과나 보정된 소스
정확도 판정이 아니며, 개발용 국소 시험 영역이다.

각 지역의 이전 기준 카메라 3개에서 stride 8로 Prior context를 만들고, 실제
판정·대조 패치의 원 픽셀들을 추가한다. 두 조건에 같은 표본 규칙을 적용한다.
평가 참조로 영역을 만들거나 문턱을 조정하지 않는다. 64px 확대 영역을 수정 범위로
확장하지 않으며 빈 깊이·법선을 보간하지 않는다.

다른 기준 카메라에서 같은 옛 표면을 관측한 Prior seed는 실제 7×7 Prior 창으로
재투영되고 깊이도 0.25m 이내인 경우에만 교체 대상으로 연결한다. 제거/추가되는
원 ID와 개수를 남긴다. 무조건적인 dilation, 큰 bbox 삭제 또는 voxel 합치기는 없다.

선택 패치를 이웃 영상에 투영한 결과는 진단 정보다. 새 MVS 감독으로 자동 승격하지
않는다. 그곳에 기존 Prior 감독을 유지해 서로 당기는 문제를 피하기 위해 해당
투영 지원 픽셀의 깊이·법선 감독을 두 조건에서 공통으로 유보하고 RGB는 사용한다.

## 두 조건과 세 비교

- `prior_only`: 같은 표본 구성에서 Prior 표면으로 초기화하고, Prior 깊이·법선 및
  현재 RGB로 최적화한다. 대응하는 선택 패치의 Prior 기하는 같은 범위에서 움직일 수 있다.
- `source_selected`: 허용된 패치에 MVS 표면을 채택하고 나머지는 Prior로 유지한다.

원 소스 점군에서 두 조건을 비교하면 소스 선택·구성의 효과다. 각 조건의 GS
iteration 0과 이후를 비교하면 최적화의 효과다. 마지막으로 두 조건의 final을
비교한다. 입력 교체 시 생긴 이동을 GS가 학습으로 개선한 양으로 합쳐 보고하지 않는다.

## 최적화

고정 Docker의 stock `gsplat 1.4.0` 2DGS renderer와 Adam을 사용한다. 과거 native
GeoGS fork 또는 별도 depth CUDA overlay는 사용하지 않는다. 원래 integer RGB 광선과
gsplat 픽셀 중심을 맞추는 camera adapter를 GPU fixture로 검증한 뒤 학습한다.
출력 깊이는 gsplat의 alpha 가중 Gaussian 중심 깊이이며 실제 surfel 교차 깊이와
구분해 표시한다.

이번 1차 비교는 2,000 step의 제한된 기술 실험이다. 선택 표면 안의 중심·방향·크기·
opacity만 기하 최적화하고, 밖의 해당 파라미터는 고정한다. 색은 현재 RGB로 맞출 수
있다. 중심은 각 조건의 초기 구성에서 최대 0.25m, 방향은 10도, 크기는 0.5–2배로
제한한다. densification/pruning은 끄고 source ID를 유지한다. 표준 2DGS 전체 학습의
수렴 또는 새로운 업데이트 알고리즘의 우월성을 주장하지 않는다.

RGB/SSIM, 채택한 깊이·법선, 2DGS 법선/왜곡 정규화와 피복 항을 사용한다. 작은
패치가 전체 영상 평균에서 사라지지 않도록 대상과 context의 고정 유효 표본을 따로
정규화한다. 이미지 손실의 분모를 수정 후 alpha에 따라 줄이지 않는다. 모든 가중치와
상한은 config로 고정한 개발 규약이며 데이터 오차의 확률 보정값이 아니다.

## 반드시 남길 결과

1. 원영상과 두 원깊이.
2. 부호 있는 깊이 불일치와 원 유효 영역.
3. 같은 이웃의 가시성·사진 지지·깊이 비용곡선 근거.
4. MVS 채택 / Prior fallback / 판단 유보 영역 및 원 ID.
5. 실제로 조립한 두 3D 소스 표면과 변경/유지 표본.
6. iteration 0/50/200/500/2000의 손실·피복·형상과 실제 변경 파라미터.
7. 같은 시점·같은 측정 창의 전후 형상·영상 적합도.
8. 주변 및 외부 구조 변화와 별도 UAS 평가의 개선/손상/피복.

UAS는 모든 학습 결과의 봉인 뒤 별도 평가 컨테이너에만 제공한다. 같은 원 reference
ID를 전후 비교하고, 공통 유효와 피복 손실을 함께 기록한다. 사진 적합도나 MVS
자기일치를 독립 기하 정확도로 해석하지 않는다. 기존 좌표계·수직 기준 한계는 유지한다.
모바일 PNG/PDF와 단계별 웹 화면을 자동 생성한다. 아직 없는 결과는 대기 상태로
보이며 0이나 성공으로 표시하지 않는다.

## 실행과 완료

기존 MVS/PGSR queue가 우선이다. 입력 준비와 CPU 검증은 먼저 수행하고, 기존 queue의
학습 단계 종료와 GPU0의 안정적인 유휴 상태를 확인한 뒤 한 GPU에서 순차 실행한다.
기존 학습·서비스·원본·checkpoint는 변경하지 않는다. 소스/config 전체를 별도
snapshot으로 고정하여 백그라운드 실행 중 workspace 변경의 영향을 받지 않게 한다.

GPU fixture, 모든 조건의 유한 loss/gradient, 범위 밖 기하 보존, 출력/참조 계보,
단계별 보고서 생성을 완료 조건으로 삼는다. 실패 시 자동 재시도하거나 과거 결과를
덮지 않고 실패 단계와 부분 산출물을 보존한다. 완료 여부는 queue 상태와 receipt로
확인하며 과학적 판정은 null로 남긴다.
