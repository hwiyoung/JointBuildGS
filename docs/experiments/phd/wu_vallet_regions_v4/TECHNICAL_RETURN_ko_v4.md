# P1·P2·P3 Wu–Vallet: 융합 전후·레퍼런스 비교와 남는 문제

2026-09-07 · `PHD-WU-VALLET-REGIONS-v4` · 비확증 개발 · `scientific_verdict: null`

**P1/P2에도 교정한 Wu–Vallet 점군 갱신을 실제 실행했고, P3를 포함한 융합 전후·현재 UAS 참조를 정량·정성 비교했다.** [비교 화면](http://127.0.0.1:8900/)은 동일 시점·높이 색의 `과거 ALS / 현재 영상 기하 / Wu 결과 / UAS 참조` 4패널, 단순 합집합, 별도 OpenMVS, 전체 native 단면·정량·실제 사진을 제공한다. 기존 8897–8899와 v1–v3 산출물은 보존했다.

관측 지원을 보강하면 P1과 P2에서 Wu가 실제로 개선한다. P3에서는 영상 단독의 결손을 보완하지만, ALS 단독에 비해 편차와 일부 결손이 커진다. **기존 방법이 해결한 부분과 남은 부분이 함께 나타났으며, 어느 한쪽만으로 결론 내리지 않는다.** 저자 코드·PSMNet·실측 궤적을 갖춘 완전 재현은 아니며, 아래 수치는 명시한 대체 입력·구현 선택에서의 개발 결과다.

## 1. 무엇을 실행했는가

P1/P2 각각 원점 ALS·GPS time·pulse·scan 순서를 재생했다. P1 ALS 20,189점, P2 45,986점 전량의 원행을 확인했고 다중반사 기반 센서 위치 추정의 5설정×2strip 모두 내부 검사를 통과했다. 전량의 대상 점에서 지원되는 추정 기점을 얻었다. 실측 궤적 정확도를 입증한 것은 아니다.

단일 현재 master의 COLMAP depth로 만든 native sensor mesh와 ALS scan mesh를 양방향 광선으로 비교했다. 거리 0.3m, 면적 0/0.25/1/4m², area1에서 원시 SINGLE 추가를 배제한 조건까지 각각 5개 출력을 만들었다. 기본 1m²는 P3에서 쓰던 값을 그대로 적용했다. 작은 new 변화영역을 다시 추가하던 v2 결함은 v3의 교정 정책으로 처리했다. 모든 결과는 원점 부분집합이며 GS·정합·평활화·좌표 평균은 실행하지 않았다.

## 2. P1의 초기 실패처럼 보였던 부분을 분리했다

P1 image838은 prism 모서리와 MVS 점이 모두 프레임 안에 있지만, 전경 지붕이 시선을 가리고 유효 깊이 지원도 부족했다. prism 방향 광선 127,612개 중 앞쪽 깊이 62,290개, 무효 깊이 32,818개, 뒤쪽 깊이 31,373개, 내부 깊이는 1,131개였다. XY가 같은 깊이 중 Z 하한 아래는 0개여서 낮은 지면의 Z 절단이 주원인은 아니었다.

기존 113뷰 전체를 검사하니 처음 40개 밖의 image90이 안뜰을 직접 내려다봤다. 별도 source-support 감사에서 MVS가 있는 3,573셀 중 영상 깊이가 지원하는 셀은 **93→3,513(2.6%→98.3%)**으로 늘었다. 선택에 사용한 edge-filter 후 메시 셀은 3,508개로, 감사의 전체 depth 셀과 분모가 다르다. P2도 같은 절차로 **69.8%→90.3%**의 지원을 확보했다.

따라서 P1 기본 결과의 한계를 그대로 Wu의 변화 판정 한계로 귀속하면 잘못이다. 기본 결과·선택 영수증·사진은 보존하고 지원이 충분한 시점의 같은 알고리즘 결과를 추가했다. [P1 지원 사진](/media/innopam/InnoPAM-8TB/hwiyoung/code/JointBuildGS-artifacts/phase-payloads/phd/wu_vallet_regions_v4/PHD-WU-VALLET-P1-VISIBLE-IMAGE-SUPPORT-v4/run/P1_selected_support.png).

## 5. 논문이 해결한 부분과 우리의 기여 후보

[원문 분석틀](PAPER_GUIDED_ANALYSIS_ko_v4.md)에 따라 해석하면 다음과 같다.

1. **이미 해결한 부분을 인정한다.** 정적인 기존 LiDAR 보존과 실제 변화 부분의 선택 갱신은 Wu의 기존 기여다. 관측지원 P1/P2의 결과가 그 효과를 보여준다. 이 전략 자체나 시점 후보 범위 확대를 새 기여로 주장하지 않는다.
2. **판단 공백 후보는 양쪽에서 다르다.** P1/P2는 현재 관측이 부족하거나 mesh가 없는 old를 어떤 범위까지 사용할지, P3는 변화를 지지하는 듯한 current 기하 자체가 틀릴 때 이를 어떻게 검증할지다. 둘을 같은 ‘충돌점 제거’로 합치지 않는다.
3. **검증할 수정은 후보별 현재 사용성이다.** 관측 가능성과 미판정을 구분해 old 유지·보류 범위를 정하고, 새 기하는 다른 현재 시점의 관측과 불확실성으로 따로 확인하는 후보가 있다. 기존 ray·크기 정제, 단순 합집합, 원시 SINGLE 일괄 배제, 강한 영상 기하 생산을 대조해야 한다. 실제 변화의 갱신과 구조 지지까지 유지되어야 기여가 된다.
4. **입력 차이를 통제해야 한다.** 현재는 PSMNet 재학습·다중 시점 전방교차를 COLMAP depth로 대체했다. P3의 영상 오류가 원문 입력 생성이나 더 넓은 정제 설정으로 해결될 가능성이 남아 있다. 이를 통제하지 않은 결과를 원논문의 확정 실패로 부르지 않는다.
5. **B의 기여는 별도로 확인한다.** 현재 텍스처·관측 세부·일관된 표면으로 확장하는 것은 별도 연구 질문이다. 같은 B에 Wu 선택 점군과 우리 선택 점군을 각각 넣고, B 자체 수정 전후도 나눠야 한다. 이번 점군·레퍼런스 비교는 실제 GS 렌더/텍스처 품질 비교를 대신하지 않는다.

따라서 현재는 **기여 후보를 뒷받침할 구체 사례와 통제 조건을 얻은 단계**다. ‘Wu가 안 된다’가 결론이 아니며, 관측지원 P1의 큰 개선과 P3의 잔존 문제를 동시에 설명해야 한다.

## 6. 재현·검증·보존

고정 crop·source·시점 선택·레퍼런스 경계는 [프로토콜](PROTOCOL_ko_v4.md)에 기록했다. 구현·설정은 `scripts/phd/wu_vallet_regions_v4/`, `configs/phd/wu_vallet_regions_v4/`, 앱은 `src/apps/wu_vallet_regions_v4/`다. 실행은 `run_docker.sh <stage> <P1|P2|ALL> [새 run ID] [설정 override]`로 source snapshot과 고정 Docker image를 남긴다.
