# P2: 단면과 3D 표시의 차이, Anchor 효과를 분리하는 비교

2026-09-10 · 기존 결과·실제 브라우저 확인 및 후속 설계 · `scientific_verdict: null`

## 1. 현재 3D 화면에서 차이가 약한 이유

사용자가 지적한 유사성은 실제 화면에서도 관찰된다. ④ ALS 초기화 GeoGS 원설정30k와 ⑤ SfM 초기화·Anchor 생략8k는 서로 다른 실제 표면이며, 전체 지붕 배치와 외곽은 비슷하다. 이전의 “차이가 명확하다”는 표현은 X=134m, 폭0.5m의 확대 단면에서 보이는 국소 차이에 한정한다. 전체3D에서 똑같이 뚜렷하다는 뜻으로 확대하면 안 된다.

현재 viewer.js의 표시를 읽고 기존 서비스8902를 Docker Chromium에서 직접 확인했다.

- 1800×1240 브라우저에서 P2 기본 카메라는 약0.1592m/화면픽셀이다. 화면 평면 방향의0.5m 차이도 약3.1픽셀이다. 이는 이번 검사창 기준이며 사용자의 실제 창 크기나 현재 카메라를 읽은 값이 아니다. 시선 방향 차이는 투영에서 더 약해질 수 있다.
- 높이 색상은 P2 전체 Z 범위−49.386~−17.679m에 공통 적용된다.0.5m는31.707m 색상 범위의 약1.58%다. 색이 비슷해도 근접도나 굴곡이 같다는 뜻은 아니다.
- 실제 메시 표시에는 `MeshBasicMaterial`을 사용한다. 면의 기울기와 조명에 따른 명암이 없어 굴곡을 읽는 단서가 약하다. 점 표시는 기본1.5픽셀 고정 크기이며 각 조건 최대200,000개의 화면용 표본이다. 평가에는 별도 전체 표본을 사용한다.
- 단면은 `abs(X−134)<0.25m`인 좁은 표본 띠다. 전체3D는 X110~158m의 모든 표면을 그린다. 동일 방향에서 보더라도 그 사이의 다른 지붕과 벽이 겹치므로 단면과 같은 내용이 보이지 않는다.

실제 카메라만 X방향으로 돌리고 중심을 약[134,100,−30]으로 옮겨4배 확대했다. 이 화면에서도 앞쪽 연속 표면이 내부의 반복 지붕 단면을 가렸다. 원설정과 생략 표면의 상단 윤곽·결손 차이는 보이지만, 단면의 반복 굴곡을 그대로 관찰할 수는 없다. 따라서 단순 확대만 권하는 것으로는 부족하다. 직접 대응시키려면 원자료는 유지하면서3D 표시에서만 동일한 X=134±0.25m 띠를 남기고, 동일 축척과 참조 중첩을 제공해야 한다. 해당 절단 UI는 이번에 구현하지 않았다. 참고로 현재 `참조 거리` 색상은 **점 모드에만 적용**되며 메시 모드에서는 소스 고정색을 유지한다.

기존 고정 단면과 전역 거리 분포의 근거는 [이전 해석](P2_NATIVE30K_VS_SFM8K_INTERPRETATION_ko_v1.md)에 있다. 국소 단면만으로 전역 F1 차이의 원인을 모두 설명하지 않는다. 표면 파일·평가 범위·수치·공유 viewer·서비스는 바꾸지 않았다.

## 2. 기존 자료로 가능한 분석

동일 UAS 참조점별로 두 조건 모두 근접/원설정만 근접/생략만 근접/둘 다 멂을 구분해 위치를 확인할 수 있다. 기존 P2 raw512·0.5m 결과에서 원설정만 근접한 참조점113,590개, 생략만 근접한 점18,528개다. 전역 분포와 국소 단면을 연결해 기복 손실·편향·결손·잘못 남은 구조를 구분할 수 있다. 참조 부재는 복원 실패와 구분한다.

Anchor8k→동일 경로 최종30k는 이후 refinement에서 무엇이 변했는지를 보여 준다. 동일 Anchor checkpoint에서 깊이 가중치와 보호 정책을 바꾼 기존 분기는 각각 **refinement 제어의 효과**를 비교한다. 이미 수행된 Anchor의 필요성을 검증하는 조건은 아니다.

현재 ALS+Anchor30k와 SfM+생략8k만으로 초기화·Anchor 경로·학습량 각각의 인과적 기여율을 추정할 수는 없다. 차이가 어디에 있는지 분석하는 것과 그 차이를 특정 요소에 귀속하는 것을 구분한다.

## 3. 최소 추가 조건과 질문

| 초기화 | Anchor 수행 | Anchor 생략 |
|---|---|---|
| ALS | 기존 원설정 경로 | 우선 추가할 교차 조건 |
| SfM | 후속 교차 조건 | 이번 생략 경로 |

먼저 ALS 초기화+Anchor 생략 조건이 유용하다. 동일 총 업데이트와 입력 조건에서 원설정과 비교하면 **ALS 초기화에서 Anchor를 거치는 운영 경로의 이득**을 본다. SfM+생략과 비교하면 **Anchor가 없는 경로에서 초기화의 영향**을 본다. SfM+Anchor까지 갖추면 Anchor의 효과가 초기화에 따라 달라지는지도 볼 수 있다. 현재 SfM22k/30k는 완전 저장 산출물이 없으므로 새 교차 조건 하나만 생성해서 장기 비교가 모두 완성되는 것은 아니다.

두 예산 질문을 별도로 둔다.

- 같은 총 업데이트: Anchor8k+refinement22k 대 생략30k. 같은 총30k의 실용적 결과를 비교하고 실제 시간·메모리도 별도 보고한다.
- 같은 refinement 횟수: Anchor8k+refinement22k 대 생략22k. Anchor의 추가8k 비용을 감수했을 때 이후22k 결과에 이득이 있는지 본다.

8k 상태끼리 비교하면 초기 단계 진단은 가능하지만 Anchor 이후 최종 성능을 대신하지 않는다.22k와30k 평가는 가능한 한 하나의 생략 궤적에서 수행해 별도 학습을 줄인다. 입력·카메라·사진·seed·추출512·평가 범위와 실행 구현을 고정하고, 여러 seed/지역은 반복성 및 조건 의존성 검증에 필요하다.

Anchor를 **전체 운영 경로**로 정의하면 이후 Gaussian 배치·Adam 이력·보호 대상 변화는 효과가 전달되는 경로일 수 있다. 이들을 모두 제거해야만 공정한 것은 아니다. 반대로 **Anchor 감독 자체**만 분리하려면 동일한 초기 상태에서 학습 일정의 기준 시계, 보호 등록 시점·규칙, optimizer 유지/초기화 정책을 사전에 같게 정한 별도 실험이 필요하다. 서로 다른 Gaussian 배열에 mask 인덱스만 복사해서는 안 된다.

현재 원 경로는 Anchor 종료8k에 보호를 등록하지만 생략 경로는 step0에 등록한다. LR·SH·normal·densification은 global iteration에 의존한다. 이 차이를 숨긴 채 Anchor loss 하나만 바꿨다고 쓰지 않는다. 현 adapter는 fresh 시작과 stage_switch0을 검증한 것이므로 교차 조건은 새 구현 확인이 필요한 설계다. 이번 요청에서 새 학습은 실행하지 않았다.

## 4. 다음 비교 이전의 입력·자원 확인

최신 작업트리의 [DA3 입력 감사](DA3_INPUT_ACCURACY_AND_KILLTEST_ko_v1.md)와 `ISSUES_ko_v1.md`의 INPUT-DA3-001에 배치별 척도·이동 및 거의 상수인 깊이가 보고돼 있다. 이번 표시 감사가 그 원자료 분석을 독립 재실행한 것은 아니다. 그러나 원방법이나 Anchor의 한계로 귀속하기 전에 확인해야 하는 현재의 입력 문제다. 공통 입력이라도 Anchor 경로에 따라 해당 감독에 노출되는 시점·기간이 달라 영향이 상쇄된다고 가정할 수 없다.

후속 실험은 먼저 GT를 학습·정합·설정 선택에 쓰지 않는 입력 계약 검증을 거치고, 수정된 입력과 실행 코드를 모든 비교 조건에 동일하게 적용해야 한다. 기존 잘못된 입력 계보와 새 결과를 혼합하지 않는다.22k 정기 렌더에서 발생한 자원 실패도 먼저 검증 가능한 저장·평가 경계로 해결해야 한다. 성능 제어를 몰래 바꾸거나 과거 fresh 재시도 상한을 확장하지 않는다.

검증된 조건에서 Anchor 없이 더 적은 비용으로 필요한 기하·세부·외관·유효 구조 보존을 달성하면, **그 조건에서는 Anchor를 생략할 근거**다. Anchor의 필수성을 전제로 학위 기여를 방어하지 않는다.
