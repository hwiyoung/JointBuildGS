# DA3 사후 감사의 귀속 정정과 실제 사진·깊이 확인

2026-09-10 · `scientific_verdict: null` · 입력/기존 감사의 비확증 재검토

**DA3 입력의 정확성을 검증해야 한다. 그러나 이전 감사의 “배치별 척도 파손”, “P1 전 뷰/P2 42/57 뷰 등이 미터 깊이가 아니었다”는 확정 표현은 현재 근거로 유지할 수 없다.** 큰 깊이 차이에는 서로 다른 표면을 비교한 가림·지역 피복 문제가 섞인다. 기존 수치·입력·학습 결과는 보존하고 원인 귀속을 정정한다.

## 무엇을 다시 확인했는가

`DA3_INPUT_ACCURACY_AND_KILLTEST_ko_v1.md`, `DA3_SCALE_CONVENTION_AUDIT_ko_v1.md`, `DA3_DEPTH_VALIDITY_AUDIT_ko_v1.md`, 실제 생성·학습 코드와 봉인 배열을 대조했다. 형식·보간 검사를 통과했다는 사실과 미터 단위의 실제 기하 정확성을 구분한다.

- 공식 camera-Z·척도 복원의 나눗셈 방향에서 규약 오류는 확인되지 않았다. API가 반환 외부표정을 입력값으로 교체하므로 그 값의 일치는 내부 척도 추정 정확성 증거가 아니다. 내부 척도와 교체 전 예측 표정은 저장되지 않았다.
- 확대 후 음수5,077개는 공식 cubic 보간 overshoot로 재현됐고 학습 유효 마스크에서 제외된다. 이 문제가 큰 기하 편차의 원인이라고 입증된 것은 아니다.
- **prior도 지역 제한 표면**이다. `input/prepare.py`는 context_domain으로 ALS를 먼저 잘라 표면을 만들고, `input/prior_native.py`는 그 표면만 raycast한다. P2 context XY는[85,183]×[61,157]m이다. 같은 카메라로 raycast해도 범위 밖 실제 앞가림물이 없으면 실제 가시 표면을 보증하지 못한다.
- 따라서 이전 문서의 “같은 자세의 광선투사, 가림 정확”은 주어진 제한 표면 내부에만 적용된다. 제한 UAS와 제한 prior가 같은 뒤쪽 표면을 비교할 수 있으므로 두 기준에서 잔차가 크다는 사실만으로 DA3 파손을 확증할 수 없다.
- `DA3≈s·reference+t`의 사후 회귀 기울기와 잔차는 입력 단위 자체의 판정이 아니다. 지역마다 다른 표면·가림·깊이 범위를 비교한 회귀계수를 배치 내부 scale factor로 해석하면 안 된다.

## 동일 사진 비교로 확인한 범위

두 지역에 공통으로 사용된 같은 사진을 찾아 RGB bytes, 원 카메라 내부·외부표정, 처리 해상도 내부표정이 일치함을 독립 Docker 읽기 감사로 확인했다. 새 시각화에서도 RGB·원 K·원 표정과 봉인 원 깊이 SHA를 확인했다. 차이는 전체602×840 원 깊이 픽셀의 절대차로 계산한다. 하늘도 포함한 **출력 간 일관성**이며 건물 정확도나 정답 오차가 아니다.

| 동일 사진 | 입력 묶음 | 깊이 절대차 중앙값 | 평균 | 95% 분위 |
|---|---|---:|---:|---:|
| DJI_20241217094957_0025_D | P1 batch1 / P2 batch4 |0.88485m|1.45562m|2.47067m|
| DJI_20241217095513_0039_D | P1 batch4 / P3 batch6 |0.13578m|0.42260m|1.54176m|

첫 쌍은 앞7장의 batch membership이 같고 P1 쪽에1장이 더 있다. 배치 문맥 민감도는 실제로 있으나 어느 지도가 더 정확한지와 그 발생 원인은 미확인이다.

그러나 첫 동일 사진에 대한 이전 감사의 `DA3−UAS` 중앙값은 P1−19.75m, P2−174.59m이고, 비교 UAS 깊이 중앙값도159.12m와313.95m로 다르다. 두 DA3 지도의 전체 차이 중앙값0.885m와 구분해야 한다. 서로 다른 지역의 다른 깊이·가림 대상을 비교한 영향이 크므로 수십~수백m 차이를 배치 척도 변화에 직접 귀속할 수 없다.

두 번째 사진의 P1 batch4는 기존 감사에서 “flat”으로 분류됐지만 전체 원 지도 min/p10/median/p90/max는38.32/40.79/48.04/148.78/508.26m다. 전체 깊이가 상수라는 표현은 틀리다. 좁은 참조 투영 영역에서 낮은 회귀 기울기가 나왔다는 관찰만 남긴다.

## 기존 GeoGS 실험에 미치는 의미

원 Anchor1~8000은 DA3 깊이의 총손실 가중치가0이다. 이후 refinement는 DA3 직접 깊이 감독을 사용하고, SfM·Anchor 생략은step1부터 사용한다. 실제 입력 오류가 확인되면 두 경로가 영향을 받는 시점·기간이 달라 Anchor의 효과 해석에 큰 영향을 줄 수 있다.

현재 F1·PSNR과 표면은 **당시 실제 입력으로 얻은 관측 결과**로 보존한다. 현재 검토만으로 그 수치를 취소하거나 전부DA3 탓으로 돌리지 않는다. “GeoGS 설계의 실패”, “Anchor가 불필요/필수”, “올바른 입력에서도 동일 현상”이라는 원인·일반화 결론은 보류한다.

다음은 동일 가시 표면을 확인할 수 있는 입력·참조 범위와 pose/depth 규약부터 검증하는 일이다. UAS는 평가 전용으로 유지하며 GT로 깊이를 보정하거나 유리한 학습 설정을 고르지 않는다. 실제 문제가 확인되면 원 입력을 보존한 새 입력 버전과 동일 조건의 후속 통제를 설계한다. 이번에 DA3 재추론, 학습, 표면 추출 또는 정합 보정을 수행하지 않았다.

## 재현과 범위

- 스크립트: `scripts/phd/geogs_p1p2p3_v1/analysis/da3_visual_review.py`
- config: `configs/phd/geogs_p1p2p3_v1/da3_visual_review_v1.json`
- task-relative 출력: `input_diagnostics_v1/da3_visual_review_v1/`
- 출력: PNG8개, `summary.json`(통계·입력hash·선정·버전), `inspection.ipynb`, code/config snapshot, exact Docker command, log, exit0. 보고서는 하위`report/`에 별도 포장한다.
- 실행: Docker image `sha256:c5445549fe7f6995e0478ab9b07565da09947c1f1d54e274802dca50aa1e7f8e`, CPU2/RAM6GiB, network none, 입력과 참조 read-only.
- UAS는 해당 지역의 원`reference.npz`에서 모든점을2px cell로 투영해 최소 양의 camera-Z를 취했다. 외부 가림은 보충하지 않았다. depth/prior는 각cell중심 픽셀을 사용한다. 새 통계는 이전의 샘플링·회귀와 정의가 다르며 동일 수치 재현이라고 쓰지 않는다.
- depth의 공통색 범위는 각사례 prior·참조의2~98% 분위로 정했고 해당 범위는그림·summary에 기록한다. profile행은 참조 cell 피복이 가장많은행이다. 표시선정은 사후 설명용이며 학습·기하평가 ROI·기준을 바꾸지 않았다.
- 부수 읽기에서 존재하지 않는 `contracts/input_v1.json` 경로 검색이 실패했지만 생성·평가에 사용하지 않았다. 실제 config/camera/receipt 경로를 사용한 시각화는exit0으로 완료됐다.

### 휴대형 HTML 보고서 포장의 기술 한계

8개 원 PNG를 내장한 canonical `report/artifact.json`은 작성했으나, 보고서 패키저가3,000,000byte 상한으로 거부해 `report.html`은 생성하지 않았다. 앞선 두 포장 시도는 native chart/provenance 요구로 검증 단계에서 종료됐다. 모든 시도 로그를 보존하고 추가 포장은 중단했다. 포장용 native chart는 새 수치를 계산하지 않고 summary의3개 수직사례를 사용했다. 원 사진·깊이·비교 PNG·summary·notebook의 생성 및 검증은 이 포장 실패와 무관하게 완료됐다. 위 직접 링크에서 그림을 확인할 수 있다.
