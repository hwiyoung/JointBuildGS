# 확인 불가와 실행 기록

- 입력 구조 점검에서 설정의 `registration`과 실행 요약의 같은 이름 항목을 동일하게 읽어 `KeyError: shift_applied`가 났다. 계산 전 탐색 코드의 키 확인을 고쳤다. 입력은 바뀌지 않았다.
- 실험 지역 항공 LiDAR 패치의 건물 번호가 빈 문자열이다. 사용자 답변에 따라 원본 GroundSurface 평면 범위에 유일하게 드는 건물, 또는 범위 밖에서 1 m 안의 유일한 건물에 연결했다. 원래 판단과 좌표는 그대로다. 복수 후보와 범위 없음은 붙지 않음으로 남겼다.
- LoD2 원본의 면 ID와 WIDEN의 다각형 ID에는 `_poly` 접미사 차이가 있었다. 두 원본의 외곽·구멍 좌표가 정확히 같은 경우에만 하나의 면으로 연결한다. 첫 사전 점검의 `KeyError`를 이 원본 대응으로 해결했다.
- r7 단계 0 잠금 파일은 최초 점검 때 없었고 작업 중 생성됐다. 실험 입력 8개 및 개발용·확인용 완료 기록이 모두 생긴 뒤 해시를 확인하고 별도로 처리했다. r2와 같은 최종 코드·면 연결로 계산과 검증을 마쳤다.
- r2 첫 그림 검토에서 긴 지붕의 번호표가 JSON 안내로만 표시되는 점을 확인했다. 그림 아래에 원래 지붕 번호표를 직접 적도록 표시 코드만 고쳤다. 집계값과 연결 규칙은 같다.
- r2 최초 묶음 전달 후 보고서 첫 다섯 줄의 설명을 명확히 했다. 칸 3은 “둘 다 틀림”이고 칸 4~6의 자료 없음과 다르며, 짝 맞음 요약의 분모는 연결된 면의 평가 넓이다. 수치는 바꾸지 않았다. 최초 ZIP은 그대로 보존했다.
- r7 개발용 완료 기록은 TARGET 컨테이너의 `/out/r2/...`를 입력 경로로 저장한다. 이 작업의 읽기 전용 `TG/r2/...`와 같은 파일임을 상대 경로 및 SHA-256로 확인한다. r7 계산 전에 경로 대응을 보완하고 최종 공통 코드로 r2를 재실행했다. 기존 파생 파일 106개의 바이트 동일성을 확인했다.
- 커밋 전 기본 Git 공백 검사는 원본 발주문과 CSV의 CRLF 줄 끝을 공백으로 표시했다. 원본 발주문 바이트와 표 형식을 보존하고, 해당 검사에만 `core.whitespace=cr-at-eol`을 적용해 통과했다. 저장소 설정은 바꾸지 않았다.
