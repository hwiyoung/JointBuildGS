# Cleanup Plan

This plan documents candidates only. No cleanup was performed during the audit.

## Cleanup Principles

1. Do not delete local data or experiment outputs without explicit user approval.
2. Preserve the active FC baseline: A8 legacy terrain-off remains the current empirical reference.
3. Keep reproducibility assets in git: source, configs, design docs, curated reports, decision files, aggregate CSVs, manifests, and small QA notes.
4. Keep raw payloads out of git: checkpoints, TensorBoard files, raw renders, evidence banks, PLY/NPZ/KSPLAT exports, per-building readout payloads, logs, pids, and local datasets.
5. Make cleanup commits separate from source/config changes.

## Phase 2: Local Generated Artifact Cleanup Candidates

Status: approval required.

Do not run these now. Candidate cleanup groups:

| Candidate | Current evidence | Risk |
| --- | --- | --- |
| Python bytecode caches | `legacy/planarsplat_ref/__pycache__`, `scripts/**/__pycache__`, `src/**/__pycache__` | Low. Regenerated by Python. |
| Local HuggingFace/cache locks | `data/matrixcity/.cache/` | Medium. Small, but avoid removing if data download state matters. |
| Raw checkpoints | multi-GB `.pt` files under `results/*/ckpt` and `results/*/run/ckpt` | High. Needed for local reruns/viewer exports unless regenerated. |
| TensorBoard files | `results/**/tb/events.out.tfevents*` | Medium. Useful for debugging but not curated evidence. |
| Render samples | `results/**/renders` | Medium. Useful for QA, but rerunnable from checkpoints. |
| Viewer assets | `tools/**/assets/` | Medium. Required by static viewer pages but regenerable. |
| Raw evidence banks | `results/stage3_rendered_evidence/**/*.npz`, `.ply` | High. Large and may be expensive to reconstruct. Preserve reports first. |

Recommended gate before local deletion:

1. Confirm the artifact group and exact paths.
2. Confirm whether local rerun/viewer use still needs them.
3. Move to an external archive or delete only after user approval.
4. Re-run `git status --short --ignored` after cleanup to verify no curated files were touched.

## Risks and Guardrails

- Do not treat all of `results/` as disposable. It contains the experiment ledger.
- Do not remove local `data/` or `results/phase2_synthesis/dataset/` during implementation work; current FC configs depend on those paths.
- Do not enable `L_structure`, G2, roof-wall relation placeholders, terrain-wall relation placeholders, A8_v2_joint, or Lmu7 as part of cleanup.
- Do not rely on checkpoints being in git. They are local generated artifacts.
- Do not make viewer asset cleanup before checking whether the HTML pages still load without those assets.
- Prefer small cleanup commits after source/config behavior is frozen.

## Immediate Recommendation

For the next GS-JSO implementation step:

1. Leave cleanup untouched.
2. Implement against the kept source/config surface.
3. Use existing curated reports as baseline evidence.
4. Add any new generated output under ignored `results/FC_*` or a new ignored experiment run directory.
5. Update this plan only after the new implementation defines what artifacts are required for reproducibility.
