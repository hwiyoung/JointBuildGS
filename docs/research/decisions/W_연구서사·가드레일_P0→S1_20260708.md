## Part 1 — 연구 이야기 (왜 여기까지 왔나)

**한 줄 주제**: 아이디어(드론 사진에서 만든 점으로 건물을 세운다)는 여러 번 "안 된다"를 받았으나, 파고들 때마다 원인은 아이디어가 아니라 **재는 방법·설정의 착시**였음. 즉 아직 공정하게 시험한 적 없음. 지금 감사는 마지막 설정 문제를 걷어내 공정한 시험을 세우는 단계.

### ① 문제 세우기 — 입력 바꿔치기 실험 (P0, W1~W4, 6월 중순 완료)
- **설계**: 같은 장소·같은 footprint·같은 재구성 파이프라인에 **점군만 바꿔 넣어** 최종 건물 모델의 품질 차이·실패 유형을 정량화
  - 상한(레이저): 레이저 점군(ALS, TUM 캠퍼스 ~21 pt/m²) → Roofer → CityGML
  - 대상(영상): 드론 사진+포즈 → 스테레오(MVS) → 점군 → 같은 Roofer → CityGML
- **재구성 실패**: 영상 8채 못 만듦 / 레이저 0채 (통계로 우연 아님 확인; 전처리·튜닝으로도 비회복)
  - 실패 8채 원인: 무늬 없음 6 · 커버리지 부족 1 · 구조화 부족 1
- **살아남은 건물의 품질 격차**(짝 비교 중앙값):
  - 평면 정확도(F1) −0.095 · 외곽 경계 1.20배 · 내부 경계 1.19배 · 높이 흔들림 1.34배 · 유효율 −5.4%p
  - 전부 판정 임계의 **경계선** — 지지 기준(세 지표 중 둘이 크게 나빠짐)에 아슬하게 못 미침 → **부분 지지**
  - 단, 외곽 경계·높이 평균은 동등(footprint·높이 보정 덕 = 입력에 둔감한 축)
- **결론**: 사진은 레이저를 완전히 대체 못 함, 특히 무늬 없는 지붕 → 논문의 출발 문제. G1 판정 게이트로

### ② 방향 다시 잡기 — 지도교수 피드백 (6월)
- 원래 계획: GS(가우시안을 기하+의미로 함께 최적화)로 CityGML 건물 생성이 논문의 주역
- 피드백: 방법을 내세우기 전, **왜 사진 기반이 부족한지**부터 실험(audit)으로 세워라 — 순서를 *방법 우선 → 진단 우선*으로 뒤집기
- **결정**:
  - GS의 자리 = 사진으로 안 되는 무늬 없는 지붕을 의미 구조로 채우기(P0가 세운 빈틈을 정확히 겨냥)
  - 새로움 좁히기 — "의미가 기하를 유도"는 남의 것(AlignGS). 우리 것은 **하나의 GS 공동최적화로 무늬 없는 건물 형태를 3D 모델 없이 채워 CityGML 생성**(vs 실내 소수-시점 AlignGS · vs 단계식 의미제약 MVS)
  - 무모델 원칙 = 3D 모델 만들려고 3D 모델 넣지 않기(순환 회피), 사진에서 나온 단서만

### ③ 방법 탐색 — GS 공동최적화 (6월 후반~7월 초, P2)
- **핵심 주장**: 3D 모델 없이 드론 사진만으로 구조화된 CityGML(LoD2 건물)을 **맨바닥에서 생성** — 기존 모델 다듬기(refinement)가 아님
- **네 갈래로 나눠 물음**:
  - ① 무늬 없는 지붕도 제 높이로 세우나 (생성, 미착수)
  - ② 영상 점군이 못 만든 건물을 GS가 만들어내나 (생성)
  - ③ 지붕을 레이저보다 잘게 쪼개나 (품질, "과분할")
  - ④ 면이 제자리인가 — 높이·기울기·수평 (품질, "위치정확도")
- **잣대**: 같은 장소의 레이저 결과를 상한으로 둔 상대 비교
- **실행 런 — 원인을 한 계단씩 좁힘**:
  - 조립: 영상 점군이 아예 못 만든 3채를 GS가 만듦 → 위상·높이는 레이저 추종(3/3), 표면·과분할이 격차(1/3) = **부분 성공**
  - 과분할은 후처리로 못 줄임 → 원인이 밀도가 아니라 복합 구조
  - 분기 진단: 잘게 쪼갠 면이 실구조가 아니라 **결함** — 떠 있는 면 아래 레이저 점 거의 없고 실제 층과 ±1~2.5 m 어긋남; 단순 박공은 제대로(방법 자체는 됨)
  - → **진짜 문제 = 면이 제자리가 아님(위치정확도), 과분할은 그 증상**; 결함은 복잡도와 상관
  - 여러 사진 맞대보기(다시점 일관성) 장치를 붙여봄 → 결론 불가(장치 너무 약함·측정 착시·표적 대부분 단순)
- **이 시기 큰 재정의**:
  - 결함을 **관측가능성** 문제로 봄 — 사진에 정보 있는 만큼만 되고, 없는 곳은 **단서(prior)**를 넣어야 함
  - 논문 척추 = **관측가능성 + 최소 단서**
  - **모델 없음** 정체성: 3D 모델 만들려고 3D 모델을 넣으면 순환 → 사진에서 나온 단서만 씀
  - **생성 / 품질 두 축 분리** 확립(모델이 만들어지나 / 만든 게 정확한가)
- **이 시기 배운 착시(→ 대장)**: 다층 지붕에 단일 중앙값 쓰면 ±4~7 m 오판(G2) · 모델별 높이 정렬이 "4.8배 개선" 착시(공정 비교는 공통 정렬)
- **전제**: 의미 라벨은 정답(LoD2) 오라클 → "라벨이 완벽할 때의 상한"(씨앗·깊이는 영상이라 순환 아님)

### ④ "GS가 진다" 처음 나옴 — 본비교 예비 실험 (E5 파일럿, 7월 초)
- **사전등록**: 기준 레시피와 게이트(재현·일반화)·성공 기준 3축(생성·유효성·품질)을 **결과 보기 전에 잠금**(끼워맞추기 방지)
- **8칸 비교(8-way)**: 같은 건물을 영상 점군 3종·GS 3종·레이저·정답(참조 LoD2) 나란히 세우고 **정답 기준으로 채점**
- 기대: GS가 자기 입력인 영상 점군보다 나음. 첫 지표(자기 채점)는 실제로 GS가 좋아 보임
- **정답·레이저를 세워 다시 재니 뒤집힘**:
  - 정답까지 거리: 레이저 0.25 m ≪ 영상 점군 1~2 m ≪ **GS 4~7 m**
  - 같은 건물 짝 비교: GS가 자기 입력(영상 점군)보다 **2~6 m 더 나쁨**(세 씨앗 일관 = 우연 아님)
  - 완전성·정확도도 GS < 영상 점군. GS가 앞선 건 sparse에서 **생성 개수뿐**
  - "깨끗해 보이던" 60098 = 박공 놓친 납작한 판(정답 6.7 m)
- → **자기 채점 착시(G1)** — 파일럿 낙관 뒤집힘

### ⑤ 왜 지는지 진단 — 점군 수준 (7월 초)
- 모델을 만들기 전 **점군 자체**를 세 축(생성·품질·유효성)으로 봄
- **점군 측정(같은 데이터)**:
  - 덮는 지붕: GS 4~7% ↔ 영상 점군(ACMP) 62% · 레이저 100% · raw-dense 15%
  - 형태: 법선 1모드(평평) ↔ raw 2모드(두 경사) · 노이즈 −0.69 m · "점 없음"이 지배
  - "밀도 +34.8" 헤드라인은 이상치 착시(중앙값 짝델타 +0.04)
- **두 실물 대비**: 60098 = 점군은 두 경사인데 모델이 납작(점군화가 뭉갬) ↔ 4908178 = 점군부터 평평(GS 깊이 문제)
- **결론**: "GS가 무늬 없는 곳 빈틈을 메운다" 이야기는 **점군 수준에서 미지지**(직관을 데이터로 확증)
- 단, 접기 전 값싼 확인 하나: GS가 원래 이렇게 약한 게 맞나?

### ⑥ 전환점 — 표면 장치가 꺼져 있었음 (7월 초~중)
- 설정(코드)을 열어보니:
  - **표면 모으기 장치(2DGS 핵심)가 한 번도 안 켜짐**(`w_distort=0`) — 2DGS의 기하 결과는 이 값을 100~1000으로 켜야 나옴
  - 사진 깊이 안내는 있으나 **텍스처 의존**(무늬 없으면 무력)
  - 떠다니는 점 걸러내기 문턱이 2DGS의 **1/10**(약함) · 외부 법선은 불러만 놓고 가중치 0
- 즉 **표면항을 끈 바닥 위에서 보조항만 튜닝**해 온 것 → 무늬 있으면 100%, 무늬 없으면 5%로 갈리는 결과가 설정으로 설명됨
- **결론**: 아이디어를 공정히 시험한 적 없음 — 제대로 켜서 다시 학습해야 판단 가능
- → **G4**

### ⑦ 원인 나누기 — 커버리지와 정확도는 다른 문제 (7월 중)
- "표면 장치 끈 게 유일 원인"으로 굳힐 뻔함 → 체크포인트로 두 증상을 나눠 봄
- 두 증상이 갈림:
  - **덮는 범위 좁음 = 점군화 단계 탓** — GS는 지붕 57%(무늬 없는 곳도 86%) 그렸는데, 점군화(관측 문턱 3뷰 + 이상치 제거)가 44%p를 버려 13%로 만듦 → "GS 5% 커버"는 점군화가 만든 착시
  - **정확도 나쁨 = 떠다니는 점 탓** — 렌더 깊이 오차 2.8 m, 가우시안 50~63%가 저불투명 떠다니는 점
- 점군화만 풀면(문턱 완화) 떠다니는 점 쏟아져 정확도가 더 무너짐(순이득 아님) → 떠다니는 점이 진짜 구속조건
- **결론**: 원인 하나 아님(다원인) — 커버리지는 점군화, 정확도는 떠다니는 점. 떠다니는 점은 재학습으로 뿌리부터 줄여야
- → **G4·G5**

### ⑧ 고치는 순서 — 표면 복원 재학습 (③b, 7월 중)
- 원칙: 한꺼번에 다 바꾸지 않고(마구잡이 금지) **레퍼런스 근거대로 한 계단씩** 쌓아, 어느 손잡이가 무엇을 움직이는지 분리
- 계단:
  - **1계단(표면 복원)**: 표면 모으기 켜기 + 떠다니는 점 걸러내기 강화 + 길쭉한 점 거르기 + 사진 깊이 안내 강하게(근거 2DGS·CityGaussianV2)
  - **2계단(+법선 안내)**: 형태 펴는 외부 법선 — 무늬 없이도 듣는 손잡이(근거 DN-Splatter·AlignGS)
  - **3계단(+의미 유도)**: 의미로 깊이·경계를 유도 = 논문 핵심, 따로 격리해 순증분만 측정(근거 AlignGS)
- 계단마다 통과 게이트
- 목표선: 무늬 있는 지붕 = 영상 점군만큼(~1 m) / 무늬 없는 지붕 = 영상 점군 능가
- 방향 전환 트리거(미리 약속): 3계단까지 가도 ~2.5 m 정체·무늬 없는 곳 우위 없으면 방향 전환
- 1계단(표면 복원) 먼저 재학습 실행

### ⑨ 1계단 검수 — 좋아졌으나 좋아진 곳이 문제 (7월 8일, 이번)
- 좋아진 것: 세 입력 덮는 범위 2배·오차 절반, 무늬 있는 지붕(4907184) 0.32 m = 영상 점군 대등, 정확도 천장 넘음
- 문제 셋:
  - **떠다니는 점 오히려 늘어남** (점 개수 5~8배 폭증 — 비율만 보면 준 듯한 착시)
  - **표면 모으기 사실상 안 켜졌을 의심** (규제를 너무 세게 나눠 힘 ~300배 죽음 → 실제 효과는 사진 깊이 안내뿐일 수 있음)
  - **좋아진 곳 전부 무늬 있고 잘 찍힌 지붕**
- 18채 분류 대조: **방법결함 5**(영상은 되는데 GS 못함)·무늬한계 5·정상 6·근본난이도 2
- **무늬 없는 지붕에서 좋아진 신호 0**
- **결정**: 다음 계단 전, "1계단이 의도대로 켜졌나" 감사 먼저
- → **G6·G7·G8**

  - 층2(진짜 관문 = 무늬 없이도 듣는 장치 있나): 표면 모으기 꺼졌으면 아직 시험 안 됨 → 제대로 켜 재학습(무늬 없는데 관측된 3채가 움직이나) / 제대로 켰는데 안 움직이면 방향 전환(정직한 audit)

**이야기 요지**
- P0가 문제(무늬 없는 지붕)를 세움 → GS가 답이라 믿음 → 여러 번 "GS가 진다"
- 매번 **재는 착시**·**꺼진 설정**을 걷어냄
- 지금 감사 = 마지막 껍질 벗기기
- 심사 답변: "왜 진단이 많았나" = 매번 착시를 걷어내 아이디어를 제대로 시험하려 함

## Part 2 — 되풀이 방지 대장 (실수 → 진짜 → 어떻게 막나)

**한 줄 교훈**: 실수는 거의 다 **"뭉뚱그린 숫자 하나가 진짜를 가림"**. 막는 법도 늘 같음 — 숫자+그림 같이, 건물 하나하나로 쪼개, 정답에 대고 재고, 스스로 반박.

| # | 실수(착시) | 진짜는 무엇 | 왜 속았나 | 어떻게 막나 |
|---|---|---|---|---|
| G1 | 자기 채점 착시 (60098 "깨끗함") | 박공 놓친 납작한 판, 정답 6.7 m | 만든 그 점군에 대고 채점 | 정답에 대고 채점 + 그림 확인 |
| G2 | 중앙값 착시 | 중앙값이 결함(면 1~2.5 m) 삼킴 | 대푯값 하나가 개별 결함 가림 | 건물별 쪼개기 + 그림; 숫자만 결론 금지 |
| G3 | 빈 모델 착시 ("빈 모델 0") | 성공 61 중 무효 18·무너짐 7 | 조립 여부만 세고 유효성·붕괴 안 나눔 | 세 갈래로(못 만듦/지붕면 0/빈 모델) |
| G4 | 원인 하나로 몰기 ("표면 장치가 전부") | 다원인(깊이 약함·걸러내기 약함도) | 첫 발견의 극적인 맛에 성급 | 단일 원인 단정 금지, 다원인 점검 |
| G5 | 뭉뚱그린 평균 착시 ("점군화가 절반 버림") | 건물별로 갈림(점군화 5/GS 덜 그림 7/정상 6) | 여러 건물 평균 하나로 합산 | 건물별 쪼갠 뒤 원인 나누기 |

| G8 | 켰다고 착각 ("표면 장치 복원") | 규제 너무 세게 나눠 ~300배 죽음, 사실상 꺼짐 | 규제식이 검증 없이 들어감(설계 메모 원격 부재) | 설정 코드·규제식 직접 확인; 원격이 정본 읽었나 확인 |
| G9 | 한 번 결과로 단정 (8568391) | 씨앗 바꾸면 실패↔성공 갈림 | 한두 번으로 방향 굳힘 | 두 씨앗 전 단정 금지 |
| G10 | 높이 기준 빠뜨림 | 게이트 오판, 매칭 측정 불능 | 높이 안 맞추고 거리 비교 | 높이 기준 명시; 못 재면 참고로 강등 |
| G11 | 최악 표본 일반화 (C001) | C001은 가장 나쁜 구역(전체는 덜 극단) | 표본이 최악인 걸 잊음 | 최악 구역 결과는 일반화 유보 명기 |
| G12 | 큰 한글 파일 편집 잘림 | 대량 편집이 조용히 잘림 | 셸이 한글 대량 편집을 자름 | 파일 도구로 편집; 잘리면 다른 방식 복구 |

**일하는 방식 원칙 (숫자 착시 외)**
- 판정은 사람이 한다 — 나는 숫자·관찰·선택지까지
- 스스로 반박: 가장 약한 데? 멋대로 한 가정? 정반대라면? 진짜 오래 걸리고 실패할 지점?
- 값싼 확인 먼저 — 다시 학습 전에 설정·자료부터 읽기
- 정본은 안 건드리고 실험은 딴 가지에서
- 쉬운 말로(코드명 괄호 한 번)

## 감사 뒤 이 이야기가 말해줄 것
- 감사가 "표면 장치 꺼져 있었음" 확인 → 아직도 공정히 시험 못 한 것(G4 재판) → 규제 제대로 걸어 다시 돌리기
- 반대로 제대로 켰는데 무늬 없는 지붕 불변 → 껍질 다 벗긴 결론이라 **방향 전환(정직한 audit)** 정당
- 어느 쪽이든 심사 답변 = 매번 재는 착시·꺼진 설정을 걷어내며 아이디어를 제대로 시험하려 함
